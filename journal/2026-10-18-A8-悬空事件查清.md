## 三、那 1 条 `id_changed`：去重规则说清楚

`make_id(school_slug, url)` 的构造是：

```python
id = f"{school_slug}-{栏目号}-{文章号}"     # 浙大式 URL
  或 f"{school_slug}-{sha1(canonical_url)[:16]}"  # 兜底
```

而 **`school_slug` 是按 `school + unit` 算的**（`u` + sha1(school+unit)[:8]）。
所以：

- 这条公告先在 `北京大学 / 物理学院` 站点被抓到 → `ua789e854-20f916efc37ca013`
- 后来 `北京大学 / 研究生招生网` 的「博士招生公示」栏也列了它（URL 还是 `phy.pku.edu.cn/info/1267/15082.htm`）
- 两个 unit 的 slug 不同 → **同一个 URL 得到两个 id**
- 最终去重是按 **canonical URL** 做的，留下的那条带 `ua8ae400a` 前缀
- 于是历史事件里的 `ua789e854-…` 就悬空了

**这不是"公告丢了"，是"同一公告换了归属"。** 处置：

1. `events.jsonl` 一行不动（append-only）；
2. `events_orphans.json` 每条加 `cause` 与 `replaced_by`，B 拿 `replaced_by` 就能把推送接回去；
3. 没有改 `make_id` —— 改成按 school（而非 unit）算 slug 会让**全库 id 大迁移**，
   B 的历史推送记录会对不上，风险远大于收益。留作后续单独评估。

## 四、代码改动

`tools/make_events.py::audit()`：

- 建 `url → id` 映射；悬空事件如果 URL 还在，标 `cause=id_changed` 并给 `replaced_by`；

## 六、给统筹的一句实话

这 12 条 `not_captured` 暴露的不是"事件流有问题"，而是**栏目覆盖不稳定**：
同一所学校，两轮之间选中的栏目可能不同，落选栏目里的公告就会"消失"一轮。
现在的 `site_verdict` 只判"站点级失败"，看不到"这一栏没选上"。
**真正的修法是给复旦、吉大配显式 `boards`**（上交/川大已经这么做了），
这件事我留在 A10 的台账里，没有在 A8 擅自动配置。
