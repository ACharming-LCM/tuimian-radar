## 00:35 A（数据）— 新增 `relevance` 字段：**只用于排序，绝不要用来隐藏内容**

### 一句话

公告列表默认按日期排，于是最新的**行政/科研**信息会占住列表前几位。
我加了一个三档整数 `relevance`，**只用来排序**。

### 实测要解决的问题

我修完科研栏目和标题之后，列表最前面变成了这些：

```
1. 南开大学2026-2027学年第一学期申请答辩学术博士平台评审名单
2. 南开大学2026-2027学年第一学期申请答辩学术硕士平台评审名单
3. 南开大学2026-2027学年第一学期专业学位硕士研究生论文送审平台双盲审名单
```

**这些是校内行政信息，不是招生信息。评委点开公告列表，前四条看到的都是它们。**

### 契约变更（**纯新增，老字段不动**）

`notice.schema.json` 的 `required` 多一个 `relevance`，取值 **0 / 1 / 2**：

| 值 | 含义 |
|---|---|
| 2 | 像招生信息 |
| 1 | 说不清 |
| 0 | 明显不是 |

判据在 `collector/fields.py` 的 `relevance_of()`，注释里有完整的取舍说明。

**建议排序：先 `relevance` 降序，同一档内仍按 `publish_date` 降序。**
（稳定排序，别把一档内部的时效性打乱。）

修完之后的实测效果 —— 列表前 6 条全变成招生类了：

```
1. [2档] 电子科技大学接收2027年优秀应届本科毕业生免试攻读研究生（含直博生）拟录取名单公示
2. [2档] 工学部关于选拔本科生赴美国西北大学参加2027年…
3. [2档] 材料科学与工程学院关于2025级先进材料卓越培养项目报名和选拔的通知
...
档位分布：2档 34 条 / 1档 24 条 / 0档 14 条
```

---

### 给 B

**1. 透传 `relevance`**（`/api/notices` 的 item 里带上）。

**2. 排序**：`(relevance desc, publish_date desc)`。
如果不想改默认排序，至少让前端能 `?sort=relevance` 拿到 —— 但我的建议是**直接改默认**，
因为默认列表是评委看到的第一屏。

**3. 门禁里加一条**：`relevance` 必须存在且在 `{0,1,2}` 里。

**4. 再强调一次：不要用它过滤。** 这个信号我实测过**两个方向都会错**：
```
误杀：南开「面向海外一流高校优秀本科毕业生招收直接攻读博士学位研究生简章」
误杀：电子科大「接收2027年优秀应届本科毕业生免试攻读研究生拟录取名单」
误收：北大 EMBA 招生简章
```
过滤错了的代价是**用户错过报名**，排序错了的代价只是某条公告低几行 ——
代价差一个量级，所以同一个不可靠的信号，能排不能滤。

### 给 C

列表页和匹配页都可以用它排序，**但界面上不要出现"相关度"这个标签**，
也不要有"只看招生相关"这种开关 —— 那等于变相隐藏。就让它安静地影响顺序。

### 我顺手修的第二个标题 bug（同一类问题）

排序之后我才看清：有些站的列表把**发布日期和标题放在同一个 `<a>` 里**，于是

```
北京大学2027年高级管理人员工商管理（EMBA）专业学位硕士研究生招生简章 2026-10-09
```

标题尾部挂着日期。已在 `listparse.py` 清掉，数据门禁也加了
「标题结尾没带发布日期」这条不变量。

**这两个标题 bug（连字符截断、尾部带日期）都是"真跑起来看页面"才发现的** ——
单元测试不会觉得标题难看。这也印证了我给 C 的那条安排：走查要真看，不能只加断言。
