## B（后端）— 第二十五场：确认"已过期沉底但保留"，并抓到一个藏在示例数据里的开关

> 派单：数据准确性补充 —— 确认已过期公告的标注（零改动）。
> 结论：**推送那边三条全对**；但顺手发现 **`/api/match` 那边其实一直在过滤**，
> 而原因**不在代码里，在示例数据里**。

### 一、派单要确认的三条（推送侧，全部成立）

| 判据 | 状态 |
|---|---|
| `urgency_weight = 0` | ✅ `push.py` 的 `urgency_weight()`：`days_left < 0 → 0.0` |
| 排在最后 | ✅ `_sort_key` 第一项就是 `1 if is_expired(item) else 0` |
| **仍然返回前端**（不是过滤掉） | ✅ 见门禁 `push_紧急度权重_按截止日分档且不压掉已截止` 的第 ③ 段 |

**这三条上一场已经做对了，代码一行没改。**

### 二、但派单的判据里有一条**当时不成立**：`/api/match` 默认在过滤

派单写：「已过期的公告仍然在 `/api/match` 的响应里（不是被过滤掉）」。

**实测（改之前）**：

```
/api/match 默认：{"total": 1119, "dropped_expired": 282, "dropped_mode": 113, "scored": 724}
                  ↑ 282 条已截止的被排掉了
```

**根因不在代码里**：`match.py` 那段是 `if prof.get("exclude_expired") and ...` ——
默认 `None`，falsy，本该不过滤。

**是 `collector/tools/profile-example.json` 里写着 `"exclude_expired": true`。**

而这份示例画像**代表"产品默认行为"** —— 所有人对着它调接口、生成 fixture、
写 PPT 里的数字。它替用户做了一个"压掉已截止的"的决定，**而没人会说得出为什么**。

**这就是这一晚反复出现的那个形态的又一个变种**：
不是"代码错了"，是**一个默认值藏在数据里**，于是没人去找它。

**改法**：删掉示例画像里的 `exclude_expired`（一行）。

```
改前：dropped_expired = 282
改后：dropped_expired = 0      ← 已截止的也返回了
```

**能力没删**：`exclude_expired: true` 仍然是显式开关（门禁第 ② 段验它还能用）。
**默认关、显式开。**

### 三、契约写在哪

派单说改 `server/contracts/match.md` —— **这个文件第三次出现了，它不存在**
（前两次：上一场派单、再上一场派单）。

契约写在 `contracts/api.md` §2「匹配」那节，加了一段：

- 已截止的**默认也要返回**（`dropped_expired` 默认 0）
- 三条理由（截止日可能抽错 / 学校会延期 / 补发的附件还有人要）
- `exclude_expired: true` 是显式开关，**默认关、显式开**
- 附上这次"开关藏在示例数据里"的经过

### 四、新门禁（四头钉）

`match_默认不排除已截止的_显式开关还能用`：

1. 默认画像 → `dropped_expired == 0`
2. 显式 `exclude_expired: true` → `dropped_expired > 0`（**这个能力不许被删掉**）
3. 两种口径的恒等式都成立（`total = dropped + dropped_mode + scored`）
4. **示例画像里不许再出现 `exclude_expired`** —— 防止有人"顺手加回去"

### 五、一个数字要纠正派单里的

派单写「我们 293 条 unknown」——**对**。1119 条里：
`found 319 / absent 507 / unknown 293`。

**`unknown` 占 26%**，这就是"已截止不能压掉"最硬的依据：
**四分之一的公告，我们根本不知道它截止了没。**

### 六、给决策者的一句话

**"已过期的留着"这条，推送那边一直是对的；真正的问题在别处 ——
示例数据里藏着一个开关，它让"按背景匹配"偷偷把 282 条已截止的排掉了。**

现在那个开关删了：**默认谁都能看到全部，想筛的人自己筛。**

### 契约动没动

**动了**：`api.md` §2 加"已截止默认返回 + `exclude_expired` 是显式开关"。
**非破坏**（只是把本来就该有的默认行为写清楚）。
