# A6 天津 title_fallback：把 38 条真公告从 junk 里捞回来（2026-10-18）

## 一、结果

| 指标 | 前 | 后 |
|---|---:|---:|
| 天津大学 junk | 39 | **4** |
| 全站 junk | 115 | **77** |
| `title_is_site_name` 命中 | 44 | 6 |
| `title_source=fallback` | 0 | **38** |

天津剩的 4 条正文是 **279 / 287 / 279 / 291 字**，都卡在"正文 <300"这条线上，
标题再对也没用（正文本来就不够），保持 junk 是正确判定。

## 二、判据

```python
# quality.py::title_fallback
只有 record_quality == junk 且正文 ≥300 字才尝试：
  · 逐行扫正文，跳过装饰行（字体大小/来源/发布时间/浏览次数/分享/审核/作者…）
  · 跳过本身还是站点名的行
  · 要求 8~80 字、至少 4 个汉字、不以「一、」「1.」这类小节编号开头、不以冒号结尾
  · 取第一个满足条件的行
```

天津的正文结构非常规整，所以这条规则一次就命中：

```
字体大小：                                  ← 装饰行，跳过
天津大学关于开展2027年硕博连读研究生选拔的通知   ← 真标题
来源：  发布时间：2026-10-12                  ← 装饰行，跳过
为选拔优秀硕士研究生攻读博士学位……             ← 正文
```

**捞回标题之后必须重算 `record_quality` 和 `topic`** —— 这两个判据都看标题。
只改标题不重算，会出现"`record_quality` 还是 junk，但标题已经是好的"这种半截状态。
新字段 `title_source` 明确写了来源：`detail`（正常）/ `fallback`（捞回的）/ `none`（捞不到）。

## 四、门禁

改动后门禁先红了一条：`fixtures/notices.list.json 的 total 和真数据不一致`（1043 vs 1120）。
**红的是判据过期，不是数据坏了**：A1 起 fixtures 默认排除 `record_quality=junk`
（契约 §19.2），而门禁还在拿"全部条数"比。修法是把门禁比的对象改成"可见条数"
（`record_quality != junk`），而不是改 fixtures 的语义。

```
数据门禁：0 失败 / 1 警告（方向覆盖，既有）
✅ 数据不变量全部成立
```

## 五、测试

- 正文 <300 字不回退（`none`）
- 正文里找不到像标题的行 → `none`

