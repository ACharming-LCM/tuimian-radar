### ① `POST /api/letter` —— 模板版，不等 LLM

**核心认知：演示时最有价值的不是信写得好不好，是 `citations` 逐条能点回原文。**
那是防"模型编造导师信息"的手段。所以模板版做出来的是更有意思的那一半：

- 形状照 `contracts/fixtures/letter.response.json`，fixture 里有的键一个不少；
- `citations` **全部逐字取自真实公告原文**，有测试逐条核对
  （`title` 直接等于标题、`body_text` 必须 `in rec["body_text"]`）；
- `method: "template"` + `_note` 明说**这不是模型生成的**；
- 正文里 `____` 留空一处不少（大学/专业/GPA/英语/科研/姓名/联系方式）；
- 结尾带"以上引文均来自：`<url>`"，用户复制时回链不丢。

实测（东南大学那条）的引文，两条**都是对申请人的真实要求**，且都在原文里：

```
[原文命中] (title)     公告标题: 东南大学2027年硕士研究生招生章程
[原文命中] (body_text) 公告原文: 所有考生须按要求如实填写报名信息并提供真实材料，积极配合签署《考生诚信考试承诺书》…
[原文命中] (body_text) 公告原文: （八）具有推荐免试资格的考生，须在教育部规定的时间内登录推免服务系统报名。…
[原文命中] (materials) 材料要求: 成绩单、四级、论文、承诺书、体检
[原文命中] (deadline)  截止日期: 2026-10-24
```

**引文挑选踩了两次坑，都不是小事：**

1. **第一版按"关键词命中数"排序，挑中的是「退役人员免初试」和「专项计划初试加分」。**
   对推免本科生最不相关的两句。**一封引用"退役士兵政策"的套磁信会让老师觉得学生
   根本没读公告。** 命中数不等于相关性 → 加了负向词表（退役/士兵/战功/加分/
   少数民族/专项计划…）和开场白词表（坚持/原则/拟招收/立德树人…），
   外加"太短/太长减分"。现在挑出来的是承诺书那段和推免资格报名那段。
2. **`_clip` 一开始连逗号也当截断点。** 于是"…逾期不得补办，请以原文为准。"
   被截成"…逾期不得补办，"—— **句子的落点没了，引文读起来像在说另一件事**。
   改成只认句号/分号/问号/叹号：截在逗号上是半句话，比不截更糟。
   （这个是测试抓出来的：我断言输出里有"以原文为准"，红了。）

`materials` / `deadline` 这类结构化字段拼出来的引文，`label` **不写"公告原文"**，
写"材料要求"/"截止日期"—— 混在一起会让人把"我们整理过的"当成"学校写的"，是诚信问题。
有测试守着。

### ② `GET /api/changes/history` —— "月度订阅"的凭据

数据源是 A 的每日归档（`data/out/history/index.json` + 每日 `<日期>.json`）。

实测输出：

```json
{"total": 1, "days": [{"date": "2026-10-16", "records": 78, "added": 0,
                        "changed": 0, "removed": 0, "reidentified": 0}],
 "days_with_changes": [], "first_date": "2026-10-16", "last_date": "2026-10-16",
 "source": "D:\\tuimian\\data\\out\\history\\index.json"}
```

- **`days` 从新到旧**：用户要看的是"最近发生了什么"，按老到新排会让他先翻到最早那天。
- **`days_with_changes` 单独给一份日期列表**：索引里大多数天是"0 增 0 改"，
  想看"哪几天真有动静"时不用自己扫。
- **`?detail=1`** 才带上每天完整变更报告（默认不带）。
- 归档缺失时带 `_error`，`total: 0` —— **不能给个空 days 就说"一切正常"**。

**一个要如实说的现状**：归档目前**只有 1 天**（08-16）。所以这个接口现在能证明的是
"今天在跑"，还不是"连续 N 天在跑"。演示前多跑几天 `run_daily.py` 才拿得出手 ——
这条我写进 RUN.md 了，没藏着。

### ③ 一键启动 + `RUN.md`

**这块踩了个我没想到的坑，值得记：**

第一版 `run.bat` 我存成了 **UTF-8**，里面的中文注释和 `echo` 全被 `cmd.exe`
按 GBK 解析成乱码命令，脚本直接崩：

```
'默认' 不是内部或外部命令
'""' 不是内部或外部命令
'或者找出占用者：netstat' 不是内部或外部命令
```

**`chcp 65001` 救不了** —— 解析发生在 chcp 生效**之前**。
正确做法：**`.bat` 只留 ASCII**，中文说明交给 `run.py` 打（Python 自己管编码）。

所以现在是两个文件：

| 文件 | 职责 |
|---|---|
| `run.bat` | 纯 ASCII。选 Python、传端口、跑完 pause（窗口不闪退） |
| `run.py` | 中文输出 + 体检 + 起 uvicorn。也可直接 `python run.py` |

`run.py` **先体检再起服务**：查依赖 → 查端口占用 → 查四个数据文件条数 →
查 `web/` 在不在。比起来之后报一堆看不懂的错，不如起来之前就说清。
还有 `--check` 只体检不起服务。

实测 `run.bat 8099`：体检全 ok，服务起来后 `/api/health`、`/`、`/api/changes/history`
全部 200。

`RUN.md` 写了：一条命令、起来后看哪三个地址、**健康检查哪三个数字要盯**
（`loaded` / `duplicate_ids` 必须 0 / `faculty_loaded`）、演示前 60 秒自检三条命令、
以及**挂了怎么办**六种情况（端口占用 / 白屏 / 数据读不到 / 额度墙 402 / 审核 401 /
彻底起不来），每种都给了判断方法和修法。
