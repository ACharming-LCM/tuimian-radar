## C（前端）C1 补：把四档接到 `/api/updates` 和 `/api/library`，并做逐档对账

> C1 的三条判据里，第①条「四档数字与 `/api/updates`、`/api/library` 一致」当时做不了
> —— B 的两个接口还没落地。**B3（`e2fe22f`）之后补上，现在三条全过。**

### 一、接口到底按什么分区（先读契约再写代码）

契约 §20.1：

```
updates = 发布日 ≤ days 天  且  未过期  且  非 junk
library = 其余全部（补集，不是"另外查一遍"）
并集 = 事件全集，交集 = 0
```

两个接口**都必须传同一个 `days`** —— 一边 30 一边 7，8~30 天那批会同时出现在两边
（契约里实测差 85 条）。所以下面每个窗口都是**成对取**的。

### 二、对账结果（三个窗口全过）

| 窗口 | updates | library | 和 | 事件全集 |
|---|---|---|---|---|
| days=1 | **0** | **1131** | 1131 | 1131 ✅ |
| days=7 | **27** | **1104** | 1131 | 1131 ✅ |
| days=30 | **112** | **1019** | 1131 | 1131 ✅ |

页面上的四档就是这三个窗口的数字（今天 0 / 本周 27 / 本月 112）+ 资料库（本月窗口的补集 1019），
**没有一个数是前端自己算的**。点「本周」→ 面板变成 `27 + 1104 = 1131`，aria-pressed 跟着走（已实测）。

### 三、一个必须写进代码注释的区别：事件 ≠ 公告

`/api/updates` 数的是**事件**（一条公告可能产生多条事件），
公告列表页的四档数的是**公告**（默认拒 junk 后 1005 条）。**两边数字不一样是正常的。**

我把这条写进 `daily.js` 的注释和页面上的小字里，因为不写的话，下一个接手的人
一定会去"修"这个"不一致"，然后修出一个真 bug。

**也是同一个理由，四档放在「今日更新」页而不是硬塞进公告页**：
公告页一次只取 50 条，拿它的窗口计数冒充全量就是假数（这正是 C1 一开始只加行级标记的原因）。
