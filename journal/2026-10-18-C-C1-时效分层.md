## C（前端）C1：时效分层 —— 把「今天该看的」和「2013 年的存量」分开

> 派单判据：① 四档数字与 `/api/updates`、`/api/library` 一致 ② 每张卡能看到「距今多久」
> ③ 首屏（默认档）里没有 30 天以上的记录。
> 做完 ②③，① 等 B1（那两个接口还没落地）。

### 一、先量，再决定做在哪一页

派单写的是"列表/推送顶部"，但我先量了一遍，发现**真正的雷不在那两页**：

| 页面 | 前 20~30 条里 >30 天的 | 第一条是什么 |
|---|---|---|
| 推送页 | **0 / 20**（19 条 ≤30 天，1 条无日期） | 北京大学 2027 EMBA 招生简章 |
| 公告列表页 | 0 / 50（默认按发布日倒序，只取最新 50） | 大连理工 10-16 |
| **匹配结果页（`/`，就是打开的第一屏）** | **11 / 30（37%）** | **「关于申报北京大学 2026 年（总第 22 批）优秀博士后奖的通知」** |

匹配页按**契合度**排序，不看新旧 —— 于是"博士后奖""赴国（境）外交换项目"全浮到前面。
**这正好是派单里说的"随便点一条大概率是已过期或博士后奖"。**

所以四档条挂在：**匹配页（第一屏）+ 推送页**，公告页只加行级标记（理由见三）。

### 二、⛔ 我第一版把四档做成了互斥区间，是错的

派单写的是 `今天 ≤1 / 本周 ≤7 / 本月 ≤30 / 资料库 >30` —— **这是包含关系，不是四个格子**。
我第一版写成"本月 = 8~30 天"，实测立刻露馅：

```
推送页点「本月」→ 17 条
可这 20 条里明明有 19 条 ≤30 天
```

**点"本月"却看不到"本周"的东西，用户只会认为东西少了。**
改成 `inTier(days, key)`：`month` 判 `d <= 30`，`library` 判 `d > 30`。
修正后同一个页面：本周 2 / 本月 **19** / 资料库 0 / 日期未知 1 = 20 ✓

> 教训：**筛选器的标签是"≤N"，实现就不能是"上一个 N 到这一个 N"。**
> 这两个读法在 N=1 时不产生差别，所以前两条档位测不出来 —— 要到第三档才炸。

### 三、公告页为什么没有四档条

四档的**计数**必须在全量上算，而公告页一次只取 50 条（`/api/notices` 目前没有日期参数，
实测 `since` / `days` / `publish_after` 传什么 `total` 都还是 1120）。

**拿"本页 50 条"的计数去冒充全量，比不做更糟** —— 那正是这个项目一直在防的"看起来有数、其实是半截"。
所以公告页这一档只加**行级**标记（距今多久 + 半年以上折叠），切换条等 `/api/updates`、`/api/library` 落地再接。

### 四、做了什么

**`common.js`（一处实现，三个页面共用）**
- `TIERS` / `DEFAULT_TIER='month'` / `ARCHIVE_DAYS=180`
- `ageDaysOf()`：**优先用接口的 `age_days`**（A3 已算好），拿不到才按 `publish_date` 现算。
  实测两套口径 **1111 条全部一致**（另 9 条无日期）。三个接口目前都还没透传 `age_days`，
  一旦透出来就以后端为准 —— 口径只留一处。
- `ageText()`：今天 / 昨天 / N 天前 / N 个月前 / N 年前
- `inTier()`（包含关系）、`tierCounts()`（累计计数）、`tierChipsHTML()`、`ageBadgeHTML()`、`archiveBlockHTML()`
- 日期一律手工拆年月日、两边按 UTC 拼：`Date.parse('2026-10-16')` 在东八区会早 8 小时，
  跨日时把"今天发的"算成"1 天前"（和 `deadline.js` 那条坑同源）。

**匹配页**：四档条 + 默认「本月」+ 计数在完整结果集上算 + 空档文案（"不是没匹配到，是都不在这个时间范围"）。

**推送页**：四档条挂在 `#list-head`（**没有复用 `#tier-bar`** —— 那个是"免费/订阅"身份条，
同一个词两个意思，state 里命名为 `ageTier` 分开）。
每张卡多一行「发布于 N 天前」：`push-when` 说的是**检测到**的时间，公告发布是另一件事，
只给一个数用户会拿检测时间判断新旧。

**半年以上**：卡片压暗 + 灰色「历史」标记 + 详情默认折叠（`<details>`，不是删掉 —— 倒查还要用）。

