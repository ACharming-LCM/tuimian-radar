# A13 relevance 重算 + 派生字段刷新（2026-10-18）

## 一、问题（B 的 issues/010，复核成立）

9 条记录的 `relevance` 是旧分数（天津 6 / 北大 3），而 relevance 是首屏**第一排序键**，
所以它们排在错误位置，门禁 188/1。

根因不是"某处忘了一行"，是 **A6 改了标题、派生字段却留在旧值**：

```
A6 把标题 "天津大学研究生招生网" → "天津大学2027年硕博连读研究生选拔的通知"
relevance 还是按旧标题算的 2 分（旧标题里没有报考词？不，是旧标题被算成了 2）
```

更要命的是 `retain_unrefreshed` 会**把旧值一路带下去** —— 不补这一环，下次修标题、修栏目还会犯。

## 二、改法

1. **`backfill_derived.py` 加 relevance**：放在最后一步，用**刷新后的**
   `title / board / apply_mode` 算，并统计"修正了多少条"。
2. **`run_daily` 新增一步「刷新派生字段」**（`tools/backfill_derived.py --write`），
   位置在 fixtures 之后、**生成事件之前** —— 事件里带的 relevance 必须已经是新值，
   否则推送排序又错一次。
3. 这一步现在是"派生字段的唯一入口"：`record_quality / quality_hits / topic /
   topic_hits / is_fresh / age_days / admission_year / publish_date（补） / relevance`
   全在这里一起重算。

## 三、实测

```
cd collector
python tools\backfill_derived.py            # 预演
python tools\backfill_derived.py --write    # 落盘
```

```
记录 1135 条
  relevance 修正 9 条          ← 正好是 B 报的那 9 条
✅ 已写盘 data/out/notices.jsonl（1135 条）
```

复算校验：

```
python -c "逐条比对 fields.relevance_of(...) 与库里的 relevance"
still mismatched 0
```

**门禁：0 失败 / 1 警告**（方向覆盖，既有）。

## 四、防复发测试

`tests/test_derived_refresh.py`：

- 造一条"标题是招生简章、relevance 还是旧值 0"的记录；
- 跑一次 `backfill_derived.py --write`；
- 断言：日志出现「relevance 修正 1 条」、记录的 relevance 变成正确值；
- 再跑一次：修正 0 条（幂等）；
- 断言 `run_daily.py` 里确实有「刷新派生字段」这一步、且调用的是 `backfill_derived.py`。

```
python tests\test_derived_refresh.py → ✅ 全部通过
```

这条测试的价值在于：它不是"测一个数字"，而是**测"标题改了、派生字段会不会跟着改"** ——
也就是这个 bug 的真实形态。
