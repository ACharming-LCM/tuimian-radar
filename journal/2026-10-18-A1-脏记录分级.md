# A1 脏记录拦截：`record_quality`（2026-10-18）

**只标记、不删除。** 1119 条全部带上 `record_quality` + `quality_hits`，脏记录数 **115**，和协调者的粗测一致。

## 一、怎么判的

新增 `collector/quality.py`，三档：

| 档 | 条件 | 条数 |
|---|---|---:|
| `junk` | 标题是站点名/栏目名；**或**正文 < 100 字；**或**正文只有「发布时间/浏览次数/来源」 | **115** |
| `thin` | 100 ≤ 正文 < 300 字 | 102 |
| `ok` | ≥ 300 字 | 902 |

判据命中（一条记录可能命中多条）：

```
body_lt_100        71
title_is_site_name 44
body_meta_only     58      ← 其中 42 条与 body_lt_100 重叠
body_100_to_300   102
```

`44 + 71 = 115`，**两个集合零重叠**——这与协调者给的「44 条标题=站点名 + 71 条正文<100 字 = 115」完全对上。

### 阈值为什么是 100 / 300

不是拍的。正文长度分位数实测 p5=17 / p10=193 / p25=359 / p50=928：
17 字那批就是元信息框（见 `fields.ABSENT_MIN_BODY_CHARS` 的注释），所以 100 卡在它和正常短正文之间；
300 是"一段完整通知"的常见下限。

### `body_meta_only` 的第一版是错的（值得记下来）

第一版写的是"有元信息词 + 没有句号 → junk"，跑出来 **junk = 156**，比预期多 41 条。抽样发现误伤了：

```
'化学学院有悠久的历史，可追溯至1929年建立的华中大学化学系…'   ← 正经正文
'10月27日晚上，生命科学学院周杨教授受邀…作分享报告。'          ← 正经正文
```

后来改成看**残留字数**：把元信息标签、日期、数字、标点全剥掉，剩下的汉字 < 50 才算"只有元信息"。
实测残留分布是两极的，中间几乎空白：

```
residue = 0     49 条（「发布时间：2026-09-29浏览次数：13」）
20~80           14 条（「…分享至：」这类尾巴）
≥100           143 条（真正文）
```

改成残留判据后 junk 从 156 落到 115，误伤清零。**教训：判据要看"剥完之后还剩什么"，
不要看"里面有没有那个词"** —— 这和 `field_state` 里 `contact` 空壳那条是同一个坑。

## 三、两个必须说清的问题（都不在 A1 范围内，但会直接影响首屏）

### 1. 上海交通大学 47 条里 **46 条是 junk**

判决依据是正文，不是我的猜测：

```
https://yzb.sjtu.edu.cn/post/3808
body_text = '发布时间：2026-10-15\n点击数：18300\n分享至：'
attachments = []
```

也就是说：**列表页能抓到条目了（0→47 确实成立），但详情页的正文是 JS 渲染的，我们只拿到元信息**。
上交只有 1 条是 ok。按现在口径，上交对首屏贡献 ≈ 0。

这不是 A1 引入的问题，但**必须让 B/C 知道**：别把"上交 47 条"当成"上交有 47 条可用公告"。
修法（下一步）：上交详情页走它自己的接口或渲染后的 HTML；在那之前，首屏会把上交整站过滤掉。

### 2. 天津大学 39 条"junk"其实正文是好的，坏的是**标题**

这 39 条 `title_is_site_name` 里 **38 条正文 ≥300 字**，内容完整（例如《天津大学关于开展2027年硕博连读研究生选拔的通知》）。
把它们判 junk 是按口径（标题不可用 → 画不出一张卡片），但**藏着 39 条真公告**，对"首屏 15 条"是损失。

我核过：从正文里能回补标题，形如「来源： 发布时间：2026-10-12」的元信息行要跳过，
真正标题在它上一行或下一行开头。建议下一步做 `title_fallback`（正文首行启发式 + 人工抽检），
把这类从 junk 提到 thin。**本轮没有擅自改标题**，因为它会影响"标题没有被截断"那条门禁，
且需要单独的验收。

## 四、怎么落盘的

```python
# crawl.py::_assemble —— 必须在 pdf.enrich 之后
rec["record_quality"], rec["quality_hits"] = quality.classify(rec)
```

放 `pdf.enrich` 之后是因为正文长度要把**附件正文**算进去，否则「正文只有附件文件名」的名单公示会被误判。

现有 1119 条用离线回填补（不联网、不重抓）：

```
cd D:\tuimian\collector
python tools\backfill_derived.py            # 预演
python tools\backfill_derived.py --write    # 落盘
```

