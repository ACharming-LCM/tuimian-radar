## 09:20 B（后端）— 第八场补记：透传 `reparsed[].why`

### 背景

A 在 `4478af3`（PDF 表格按行拼接 + extract v4）里做了一件比修 bug 更重要的事：
**把"变更归因"写成了规则。** 起因是抽取器一换正文必然不同 ——
实测把表格从"一个单元格一行"改成"按行拼接"之后，67 个 PDF 的正文全变了。
不归因的话，日报会说**「学校改了 67 份通知」**。

新的判据（契约 api.md 第 431 行）：

| 桶 | 判据 |
|---|---|
| `changed` | 正文变了**且** `extract.version` 没变，或**附件 URL 集合**变了 |
| `reparsed` | 抽取器版本不同带来的正文差异 / 只有派生字段不同 / 附件只有 `text_len` 变 |

**`reparsed[]` 因此多了一个 `why` 字段**，取值是"抽取器版本变了"/"附件抽取结果变了"/"派生字段不同"。

### 做了什么

`why` 在磁盘上有、被我的投影丢掉了。补上。

**而且只给 `reparsed`，不给 `changed`** —— 契约里 `changed` 的判据已经表达得够明确，
凭空给它加一个 `null` 键只会让前端多一个要判空的分支。
这件事是真实的：磁盘上 `changed` 的条目**本来就没有** `why` 这个键。

活接口实测：

```
counts: {'previous': 78, 'current': 72, 'added': 0, 'changed': 0,
         'reparsed': 21, 'removed': 6, 'reidentified': 0, 'unchanged': 51}

reparsed 21 条，why 分布: {'抽取器版本变了': 13, '派生字段不同': 8}

reparsed[0]:
  id   = u50d849a2-74-604480
  why  = 抽取器版本变了
  fields = {"title": ["南开大学2026", "南开大学2026-2027学年第一学期申请答辩学术博士平台评审名单"],
            "target_year": [2026, 2027], "attachments": {"old_count": 1, ...}}
  body_changed = False
  带 body_text 吗: False
```

**这个 `why` 对前端是必须的**：契约要求界面把 `reparsed` 显示成
「我们改进了抓取」而不是「通知被修改」，而"改进的是什么"就得靠 `why` 说 ——
不然用户看到一栏"我们改进了抓取"却不知道改了什么。
