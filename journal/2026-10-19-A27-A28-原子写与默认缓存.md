# A27/A28：增量落盘改原子写 + run_daily 默认走缓存（2026-10-19）

## 事故

06:25 的 `tuimian-full` 补跑（本该 03:07，机器没开）带 `--refresh` 全量重抓。A17 加的
"每 N 站增量落盘"**直接截断并重写线上 `notices.jsonl`**：

- 2751 条 → **69 条**（第一站跑完那一刻）；
- 剩下 3 小时里，服务和门禁读到的都是这 69 条；
- 收尾的 `shrink_guard`（<80% 拒写）**完全没用** —— 它发生在增量写之后，文件早被截断了。

跑完时（09:34）数据回到 2751，但 `freshness.json` 还停在 00:03 —— 进程在
`os.replace` 之后、写 freshness 之前就没了，门禁因此报"过期快照"。

## A27 改法

| 之前 | 现在 |
|---|---|
| `checkpoint()` 每站 `os.replace(tmp, out)` —— **每次都在换线上文件** | `checkpoint()` 只写 `out + ".tmp"`，**线上文件一个字节都不碰** |
| 收尾的 shrink_guard 闸在写盘之后 | 全部跑完 → `shrink_guard` → 才 `os.replace(tmp, out)` |
| 异常退出留下残缺线上文件 | 异常退出删 tmp，线上保持上一轮完整版本 |
| `.partial` 残渣 | 统一 `.tmp`；开跑前清残留 |

新增 `guarded_main()`：`__main__` 走它，异常（含 Ctrl-C）删 `<out>.tmp` 再抛。
`kill -9` 跑不到清理，但它同样没碰过线上文件，最多留一个 tmp，下次开跑前清掉。

顺带：`run_daily` 在"抓公告"之后加了一步 `rebuild_freshness --write` ——
crawl 自己在写盘后会写 freshness，但那一刻被杀就会留下"数据新、新鲜度旧"的时间差。

## A28 改法

`run_daily` 原来默认 `--refresh`。改成：

- 默认 = 缓存（只抓新 URL）；
- `--refresh` 显式全量；
- 日志第二行打印 `=== 本轮模式：缓存（只抓新 URL，默认）===` 或 `全量刷新（--refresh，忽略缓存）`。

`--no-refresh` 保留但隐藏（等价默认），旧脚本不会因为参数不存在而报错。

## 测试

`collector/tests/test_atomic_write.py`（**11 条断言，全过**）：

1. checkpoint 只写 `.tmp`，线上文件字节不变；
2. 运行期间并发读线上文件仍是完整的上一轮（50 条都在）；
3. 中途抛异常 → tmp 被删、线上仍是上一轮；
4. 子进程 `os._exit(9)` 模拟 kill → 线上完好、tmp 残留（符合预期）；
5. `_discard_tmp()` 能清残留；正常路径 `os.replace` 后才换线上文件。

`tests/test_crash_safety.py` 第 3 组同步改写：原来断言"第一个站的数据已经在盘上"，
现在断言"在 tmp 里、线上没被截断" —— 这是**语义变更**，不是放松。

## 纪律（写进这里，下轮照做）
