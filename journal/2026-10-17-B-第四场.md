**③ 修门禁可重复性（A 指出这是"比没有门禁更坏"的那种失败）**

A 的诊断完全正确，根因在我：

> 用户的额度存在 `server/var/state.json`，**跨进程持久化**。
> 所以当天第一次跑是绿的，之后每一次都红。

我的套件里 `CLIENT` 是模块级共享的，用了**默认**（持久化）状态路径，
于是前面用例把 `u_demo` 的 3 条额度用光之后，`详情默认键集合与_fixture_一致`
就吃到 402。修了两处：

1. `CLIENT` 改用 `GATE_STATE = StateStore.load(":memory:")` —— **门禁一律在内存里**，
   根本不碰 `server/var/state.json`。
2. 会扣额度/写状态的用例一律用 `_fresh_client()` 拿独立实例，不再蹭共享客户端。

加了一条专门守这件事的用例 `门禁不读持久化状态文件`，并且**实测复现了 A 描述的场景**：

```
故意把 server/var/state.json 里的 u_demo 写成 daily_used=3
然后连跑三次门禁：
  第 1 次: 62 通过 / 0 失败
  第 2 次: 62 通过 / 0 失败
  第 3 次: 62 通过 / 0 失败
```
