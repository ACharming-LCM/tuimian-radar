### 第 1 件：那句断言确实绑了数据量

```python
# 改前
need(sub["tally"]["truncated"] is False, sub["tally"])
# 改后
need(sub["tally"]["truncated_reason"] != "free", "订阅身份居然被免费层截断了")
```

**这是这一晚第六次栽在"断言绑了磁盘上恰好是什么数据"上。** 前五次是 B 时代记的
（额度状态、条数、页码、第一页假设、演示脚本第一页），这次是我自己在新代码里犯的。

值得记的一点：**`truncated` 这个布尔太粗了**。它同时表示"被免费层截了"和
"被每日上限截了"，而这两件事的含义完全相反（一个是"该付费"，一个是"设计如此"）。
断言写成 `is False` 就没法区分；写成 `reason != "free"` 才表达出真正的意图。
**一个布尔如果同时表示两种"限制"，它迟早会被误用。**

### 第 2 件：选了"排序沉底"，不压掉

用户给的两个选项：a) `EXPIRED_AFTER_DAYS` 从 7 收紧到 0（压掉并给理由）；
b) 排序上未截止的在前、已截止的沉底但不隐藏。

**选 b，而且比 b 更进一步：把压掉整个删了**（原来 `days_left < -7` 会压进
`suppressed(expired)`，现在一条都不压）。

四条理由，前三条是具体的、第四条是原则：

1. **截止日可能抽错。** 这个项目有过"把正文里的日期当成发布日"的实例（差 31 天），
   也有噪声闸误杀正确截止日的实例。压掉一条抽错的，**用户永远不知道该去报名**。
2. **学校会延期。** "截止日从 10-15 延长到 10-30"恰恰是最有价值的推送 ——
   而如果 10-15 那天把它压掉了，这条推送就不会出现。
3. **补发的附件截止后照样有人要**（模板、表格）。
4. **和"`relevance` 只排序、不隐藏"是同一条原则。**
   已截止是同一个问题：**排序错了只是某条低几行，压错了是永久看不到。**

**"已截止"的判据（严格，不许扩张）**：只认 `found` 且 `days_left < 0`。

- `absent`（公告没公布截止日）**不算** —— 归进"已截止"是编造一个我们没有的事实；
- `unknown`（我们没读到）**不算** —— 同理；
- `days_left == 0`（今天截止）**不算** —— 那是最紧急的一条，沉底就反了。

这条判据单独抽成了 `is_expired(item)`，门禁里对四种输入逐个钉过。

### 怎么验的

**反向验证**（把沉底去掉）：

```
去掉沉底后红了 ✓： 已截止的没有沉底：['e_absent', 'e_future', 'e_past', 'e_today', 'e_unknown']
```

**真实数据实测**（286 条事件，放开每日上限看全量排序）：

```
35 条命中，8 条已截止，序号 28~35
最晚的未截止序号 = 27，最早的已截止序号 = 28 → PASS（分离干净）
用户提到的那条：#29 浙江大学2027年硕士研究生招生简章
                 deadline=2026-10-15  days_left=-2  expired=True
```

**它从 #1 沉到了 #29。** 而 `suppressed` 里没有它 —— 它是被排序了，不是被压掉了。

### 一个观察（**要用户拍**，我没做）

沉底之后**首条不再是"已截止"，但也不是"有明确截止日"的** —— 现在是 `absent`
（「该公告未公布截止日」）。因为 `absent` 的公告 `relevance` 高、且它"不算已截止"。

实测前 3 条：

```
#1 [absent]  北京大学研究生招生网
#2 [absent]  北京大学 2027 年硕士研究生招生简章（校本部）
#3 [absent]  浙江大学关于报考2027年少数民族高层次骨干人才计划…的说明
```

如果产品上希望"**有明确截止日的排前面**"（因为那种才有行动力："还剩 7 天" vs
"未公布截止日"），那是**再一级分组**：

```
found 未截止  →  absent / unknown  →  found 已截止
```

这和 §14 的排序分桶（found → unknown → absent）是同一个思路，
但推送列表是 **relevance 优先**的，加这级分组等于把 relevance 降为第二级。
**这是产品判断，不是技术判断，所以我没动。** 需要的话说一声，改动很小。
