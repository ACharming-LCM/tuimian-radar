# A7 print 不许崩整轮（2026-10-18）

## 一、事故原样

```
UnicodeEncodeError: 'gbk' codec can't encode character '\ue603'
crawl.py line 433: print(f"  -> [{b['score']:>2}] {b['label']}  {b['url']}")
```

计划任务环境是 GBK（Windows 默认代码页），北大研招网的菜单文字是：

```
'\ue603 硕士招生 \ue61e 博士招生 \ue886 港澳台招生 \ue607 留学生招生 \ue622 夏令营 \ue61d 网上报名'
```

7 个**私用区码位**（U+E000–U+F8FF，图标字体）。它们是"图标"，看着像空白，
但 `print()` 遇到 GBK 编不出来的字符会抛异常，而异常发生在抓取中途 ——
**一个图标废掉整轮抓取**。

## 二、两道防线（都要有，缺一条都不够）

1. **入口兜底**：`crawl.py::main()` 第一行 `common.safe_stdout()`，
   把 stdout/stderr 的错误策略改成 `errors="replace"`。
   这样即使还有漏网的怪字符，也只会打成 `?`，不会中断。
   *为什么不能只靠这一条*：它让数据"带毒落盘"（`\ue603` 会原样写进 JSONL）。
2. **落盘前清洗**：`common.clean_text()` 删掉 U+E000–U+F8FF，在三个地方调用：
   - `discover.py`：栏目名（`own` / `parent` 两处）—— 就是崩的那一处
   - `listparse.py`：列表标题
   - `crawl.py`：`board` 字段（`b["label"]` 来自上一步，已是干净的）

**为什么是"删掉"而不是"替换成 ?"**：图标没有语义，删掉是干净文本；
换成 `?` 会在标题里留下垃圾，而且 `?` 也会进入正则匹配（标题里出现 `?` 会误导）。
兜底那一层用 `?` 只是因为**那时候已经来不及改数据了，只能保证进程活着**。

## 三、实测

### `PYTHONIOENCODING=gbk` 跑整轮（缓存命中，199 栏 × 1 页 × 1 详情）

```
$env:PYTHONIOENCODING='gbk'
python collector\crawl.py --pages 1 --details 1 --no-diff --out _scratch\gbk-test.jsonl
exit=0
seconds=17.9
```

产物里北大栏目名已经干净：

```
' 硕士招生  博士招生  港澳台招生  留学生招生  夏令营  网上报名'    ← 图标码位没了
```

95 条记录，**含私用区字符的记录 0 条**。

### 兜底那条单独验（证明它真的在起作用）

```
$env:PYTHONIOENCODING='gbk'
python -c "import common; common.safe_stdout(); print('before\ue603after ok')"
before?after ok          ← exit 0，字符被替换成 ?
```

对照组（不装兜底）：

```
python -c "print('x\ue603y')"     → exit 1（UnicodeEncodeError）
```

**这条对照是故意的**：没有它，就分不清"测试通过"是因为修好了，还是因为根本没触发。

否则摘要文件会被小样本覆盖（这条以前踩过，这回又差点踩到）。
