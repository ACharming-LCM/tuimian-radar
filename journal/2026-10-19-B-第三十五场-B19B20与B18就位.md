## ① B19：`intended_schools` 被保存、然后被彻底忽略

**改之前**（QA 的现场）：`PUT /api/profile` 传 `intended_schools` → **200**，
字段原样进了 state，但 `push.match_because` / `match_notices` 只读
`preferred_schools` —— 用户看不到任何提示，只觉得"这系统不懂我"。
QA 按 README 的固定画像跑，第一屏 **0 条**。

**改之后**（`server/profile.py`）：

- 近似字段**自动映射**：`intended_schools` / `target_schools` / `preferred_school`
  → `preferred_schools`；`major` → `majors`；`target_level` → `target_levels`；
  `wanted_mode` → `wanted_modes`；`interest_keyword` → `interest_keywords`。
  **原名不保存**（留了就一个值两个来源）。
- 真字段和近似字段都填 → **以真字段为准**，近似字段进 `dropped`；
- 完全不认识的 → `unknown_fields` + 一句人话 `field_note`，**仍然原样保存**
  （以后可能用），但明说"不参与匹配"。
- `normalize()` 从返回元组改成**返回字典**（`profile` / `dropped` / `mapped` /
  `unknown_fields` / `field_note`）—— 旧交接文档 §7.7 那条"元组传多个值顺序靠记"
  的教训，这次自己用上了。

**实测**（真实数据，`state` 用 `:memory:`）：


## ② B20：EMBA 排第一 —— 不是权重问题，是缺一个负向维度

QA 的现场（物理 + 直博 + 意向北大/清华/中科大）：

```
#1 北大 高级管理人员工商管理（EMBA）专业学位硕士研究生招生简章
#2 北大（1101）报考点公告
#3 北大 2027 年硕士研究生招生简章（校本部）   ← 真正该看的在这
```

**根因**：四维（学校/专业/方向/新鲜度）全是**正向**的，EMBA 那条 `school_hit=1.0`、
还两天后截止，紧急度 ×2.0 —— 按四维排**它必然第一**。

**改法**：加 `misfit`（契约 §18.5 / §18.8）：

| key | 命中（只扫标题） | 乘数 |
|---|---|---|
| `degree_type` | EMBA / MBA / MPAcc / MPA / MEM / 在职攻读 / 非全日制 | **0.35** |
| `transactional` | 报考点 / 考点 / 考场 / 准考证 / 网上确认 / 现场确认 / 考试安排 / 考试须知 / 复试录取工作办法 | **0.35** |

- **只降权、不隐藏**（和"已截止沉底不压掉""`relevance` 只排不滤"同一条原则）；
- 每条都有 `misfit.keys` / `text`，`text` **同时进 `why`** —— 降权可以，黑箱不行；
- **画像自己就要专硕/管理类时不降权**（只看用户明确写的 `target_levels` / 专业）。

**实测（3b 画像，2759 条事件）**：

```
#1 北大简章   #2~#5 目录/推免通知   #7 EMBA（w=0.35）   #9 报考点（w=0.35）
```

### 这轮唯一一次"第一次没修好"

`transactional` 我第一版给的 **0.8**（"轻压"），理由是报考点对已在报名的人重要。
实测**照样第 2**：报考点公告带报名截止日，紧急度 ×1.2，
`0.55 × 1.2 × 0.8 = 0.528`，仍高于普通简章的 0.45。

**教训**：**"轻压"压不住"紧急度"** —— 这两件事是乘起来的，权重差 20% 不够，
得差一个数量级（0.35）才压得动。**改完必须用真实数据看名次，不能看"权重变小了"就算完。**

### 反向验证

`TUIMIAN_MISFIT_DEGREE=1.0 TUIMIAN_MISFIT_TRANSACTIONAL=1.0` 跑门禁：

```
FAIL  push_负向维度_EMBA和报考点不许排第一

```

用例还额外造了"EMBA 原始分高于简章"的数据（两天后截止），所以它红的时候
证明的是**misfit 在起作用**，不是"碰巧排对了"。
