# A4 两档抓取：`--fast` / `--full`（2026-10-18）

## 一、`--fast` 做了什么

三件事，缺一条就变成"快但丢数据"：

1. **每栏只读第 1 页**（`pages_per_board = 1`）。第 1 页本来就是最新十几条，
   日更要的是"有没有新东西"，不是把历史重读一遍。
2. **只对"上一轮没有的 URL"抓详情**。上一轮已有的 URL 直接沿用记录，**不重新解析正文和附件**
   —— 这是省时间的大头（一轮 280+ 份 PDF，占全量耗时的多数）。
3. **把第 1 页之外的历史记录带过来**（`carried_prev`）。没有这一步，一次 fast 就能让
   notices 从 1120 掉到 300 —— 那不是"快"，那是"丢数据"。

代价写在代码注释里：**fast 永远发现不了"学校删了公告"，也不会重算老记录的字段。**
要发现删除、纠正历史、应用新的抽取规则，必须跑 `--full`。

## 二、实测

### fast（缓存命中，热）

```
开始 10:53:50
{"exit": 0, "seconds": 125.7, "before": 1120, "after": 1120}
```

**125.7 秒 ≈ 2.1 分钟**，达到"≤5 分钟"的目标。

同一次运行的统计：

```
=== 统计: {'boards': 199, 'list_pages': 199, 'listed': 1500,
          'detail_ok': 858, 'detail_reused': 856, 'new_urls': 0,
          'detail_fail': 16, 'detail_nobody': 24, 'carried_prev': 263}
模式 fast（第1页 + 只抓新 URL）  新增 URL 0 条 / 沿用 856 条 / 带过历史 263 条
记录 1120 条
变更 -> changes.md (新增 0 / 有变化 0 / 本轮未抓到 0)
```

与"只增不减"对照：跑完 1120 → 1120，**新增 0、移除 0**（上一轮已经是同一份数据，
所以新增 0 是正确的，不是"没抓到"；856 条沿用 + 263 条带过 = 1119，与 1120 差 1 条
是跨栏目重复被去重）。

### 第一次 fast（冷一点，缓存里少了 42 个新链接）

```
模式 fast（第1页 + 只抓新 URL）  新增 URL 42 条 / 沿用 856 条 / 带过历史 263 条
记录 1120 条  （1119 → 1120）
变更 -> changes.md (新增 2 / 有变化 0 / 本轮未抓到 1)
```

42 个新 URL 只落成 2 条记录，原因是 `detail_nobody 24` + `detail_fail 16`：
新链接里有一批是导航页/空壳页（例如上交详情页正文是 JS 渲染的，只有"发布时间/点击数"），
抓到了但没有正文，按既有规则不进产物。**这不是 fast 的锅，是全量也一样的结果。**

### full（对照，同一台机器、同一份缓存，本轮更早那次）

```
抓公告 975.6 秒 ≈ 16.3 分钟
```

所以两档的差距是 **16.3 分钟 → 2.1 分钟，约 7.8 倍**。

## 三、什么时候用 fast / 什么时候必须 full

| 场景 | 用哪档 | 理由 |
|---|---|---|
| 每天例行日更、只想拿新公告 | **`--fast`** | 只依赖第 1 页 + 新 URL，2 分钟内跑完，抓完就是"现在" |
| 改了抽取规则（`EXTRACT_VERSION` 升版） | **`--full`** | fast 沿用上一轮记录，不会重算老记录 |
| 想发现"学校删了公告" | **`--full`** | fast 把上一轮记录全带上，`removed` 恒为 0 |
| 新加站点/改栏目配置 | **`--full`** | fast 只读第 1 页，新栏目需要完整列表 |
| 首屏要"最新 15 条"但数据已 6 小时没跑 | **`--fast`**（可连跑两次） | 第二次几乎全命中缓存，只补差的 |

判据一句话：**fast 负责"变新"，full 负责"变对"。** 每天 fast，每周一次 full。

## 四、代码改动

```python
# crawl.py
ap.add_argument("--fast", ...)   # 每栏 1 页 + 只抓新 URL + 带过历史
ap.add_argument("--full", ...)   # 显式全量（默认就是全量，加这个只为日志可读）

if args.fast:
    lim["pages_per_board"] = 1

# 详情循环里
if args.fast and old is None:
    old = prev_by_key.get((site["school"], site["unit"], detail_key))   # 不带版本闸

# 站点循环之后
if args.fast:
    for (sch, unit, key), old in prev_by_key.items():
        if key in seen_urls or (sch, unit) not in visited_sites:
            continue
        records.append(dict(old)); carried += 1
```
