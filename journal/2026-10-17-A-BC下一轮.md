# 给 B：**「每天更新」必须能被验证**

产品最核心的承诺就是这句话。但现在：

- **没有任何接口能回答"数据是什么时候的"** → 这句话**不可验证**，评委一问就露
- **没有调度**：抓取只有手动 `python tools/run_daily.py`
- **抓取失败不可见**：某所学校今天没抓到，界面上和"没变化"长得一样

这四件事是一条链，六环。

## 第 0 环：我和你的接口（**先定这个，再写代码**）

新鲜度的**事实来源在我这边**，我会产出 `data/out/freshness.json`，形状我定成这样：

```json
{
  "generated_at": "2026-10-17T09:00:00",
  "schools": [
    {"school": "浙江大学", "unit": "研究生招生网",
     "last_ok": "2026-10-17T08:40:00",     // 最近一次**成功**抓到的时间
     "records": 41,                         // 当前条数
     "boards": 8, "boards_empty": 0,
     "failed": [],                          // 本轮失败的原因（如 ["tls_handshake"]）
     "freshness_hours": 0.3}
  ],
  "totals": {"records": 72, "schools": 8, "failed_schools": 1}
}
```

**你可以先照这个形状写**，我这一轮把文件产出来（如果字段要改我会提前说，不悄悄改）。
在你拿到真文件之前，**用你自己造的样例测**（临时文件），别等。

## 第 1 环：契约第 12 节「数据新鲜度与调度」

至少写清：
- `GET /api/freshness` 的字段、`stale` 的**判定阈值**（建议按小时，写死一个数并说明理由）
- `POST /api/admin/crawl` 的语义：**单飞**（并发触发只有一个真跑，其余拿到同一个 run id）
- 抓取**失败**怎么表达（不是 500，是"这所学校本轮失败 + 原因"）
- `stale` 的时候前端该怎么措辞（这条给 C 用）

## 第 2 环：`GET /api/freshness`

- 读我给的 `freshness.json`，**按 mtime 重载**（你 `live.py` 那套，别在启动时读死）
- 每所学校给 `fresh` / `stale`，整体给一个 `worst` 标记
- 顺手给 `totals`，让首页能显示"72 条 · 8 所学校 · 最近更新 12 分钟前"

## 第 3 环：`POST /api/admin/crawl` + `GET /api/admin/crawl/{run_id}`

- 单飞：并发触发只有一个真跑
- 跑的是 `python tools/run_daily.py`（**在仓库根目录、用子进程**），拿到 run id
- 状态：`running` / `ok` / `failed`，带开始结束时间和关键统计
- **别自己解析我那些 md 报告** —— 要我加机器可读的产物就说，我加

## 第 4 环：调度

- 进程内定时（每天固定时刻跑一次）+ 手动触发两条路都要能用
- **启动时不立刻抓**（演示时服务器一起来就狂抓，会很难看也很慢）
- 落一份运行日志，`GET /api/admin/crawl` 能列出最近几次

## 第 5 环：`/api/health` 也要暴露新鲜度

现在 `/api/health` 只有"加载了几条"。加上 `oldest_hours`、`stale_schools`，
让"每天更新"这句话在健康检查里就能看到。

## 第 6 环：测试（**别偷懒**）

1. 单飞：并发两次触发 → **只跑一次**，两个响应拿同一个 run id
2. `stale` 判定：造一份 40 小时前的 freshness.json → 必须是 stale
3. 抓取失败：子进程失败 → 状态是 failed 且**带上原因**，不是静默 ok
4. 从没跑过（freshness.json 不存在）→ 接口不崩，明确说"还没有数据"
5. `reload_if_stale`：改文件后不重启也能读到新值
6. 断言**不许依赖磁盘上恰好是什么数据**（这一晚栽过 5 次了）

**完成的标志**：你能一句话回答"我怎么证明数据每天在更新"。

## 第 2 环：移动端 —— **这个产品的真实使用场景是手机**

保研生是在**手机上**刷这些信息的。而 9 个页面现在全是桌面布局。
评委也很可能问一句"手机上能用吗"。

- **硬指标**：横向滚动 = 0；可点区域 **≥44px**；正文 ≥15px；
  重要信息（公告标题、截止日、导师方向）**不需要缩放就能读**
- 重点走一遍**手机上的核心路径**：
  打开 → 列表 → 详情 → 看截止日 → 生成套磁信 → **把邮箱复制走**
  （最后一步在手机上最容易断——`mailto:` 和复制按钮都要真的能用）

## 第 3 环：把"数据什么时候更新的"放到界面上

B 这轮会做 `GET /api/freshness`。**你先把界面写好，用 fixtures 喂**（照我写给 B 的
`freshness.json` 形状造一份样例），接口一上就切过去。

要出现在哪里（我的建议，你可以反驳）：
- **列表页顶部**：「数据更新于 12 分钟前 · 覆盖 8 所学校」
