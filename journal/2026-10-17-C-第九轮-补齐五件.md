### ① 三态措辞落到 列表 / 详情 / 匹配 三页（**契约里唯一带 ⛔ 的一条**）

**改之前**：`notices.js` 和 `match.js` 都是 `if (!r.deadline) return '';` —— 没截止日就整行不显示。
`detail.js` 更直接：`deadline ? '截止 X' : '公告未明确截止日期'` —— 把「我们没读到」说成了「确实没有」。

这正是契约 §14.5 用 ⛔ 明令禁止的：**`unknown` 和 `absent` 被合并成"什么都不说"，
用户会以为这条没有截止日，于是不去看原文。**

**数据早就给了**（我这次才把三处对上）：
| 页面 | 数据来源 | 说法 |
|---|---|---|
| 列表 | `?meta=1` → `field_trust.states.deadline` | 三态齐全 |
| 详情 | `?meta=1` → `deadline_display`（服务端拼好的） | 三态齐全 |
| 匹配 | `/api/match` **不给**任何三态字段 | 只能按 `unknown` 说 |

做法：三页都改成调 `deadline.js` 的 `deadlineLineHTML()`，
并让 `deadline.js` 多认一种输入（`field_trust.states`，列表接口的形状）。
**措辞仍然只有一份实现**，页面只负责排版。

> 匹配页那条是真缺口：`/api/match` 的 item 不带 `field_state` / `field_trust`，
> 所以它只能写「未能读取截止日，请点原文核对」。那是**最安全的一句**（它让人去点原文），
> 但丢了 `absent` 那一档。要补得让后端在 match 的 item 里加 `field_trust` —— 已转给 B。

**顺手抓到的文案自相矛盾**：列表页导语还写着「抽到截止日才显示，抽不到就不显示」，
页脚写着「抽不到的时候卡片上就不显示截止日」。**屏幕已经改成三态了，文字还在说旧行为。**
`notices.html` 和 `index.html` 的这四处都改了 —— 这是"文字和屏幕打架"的典型，
比功能没做完更容易被评委当场问到。

### ② 列表页「保留筛选」刷新

`live.js` 发现后台数据变了会发 `tuimian:data-updated`，`notices.js` 现在监听它：
重拉数据 → **学校/单位/方式/搜索词/只看附件/排序全部保留** → 重渲染。

两个细节：
- **不能**再调一次 `renderToolbar()` —— 那会重复绑定 `change` 事件，用户选一次学校会触发两次渲染。
  所以拆出 `refreshToolbarCounts()`：只重建选项和计数，把当前选中值放回去。
- 选中的学校这一轮可能已经不在列表里 → 自动退回「全部」，否则用户会看到"选着浙大却一条都没有"。
- 重拉失败**不换掉已有列表**（那些数据仍有效），只在上面加一句提示。

实测：选「天津大学」→ 触发更新 → 仍然是「天津大学、8 条」，`filterKept: true`。

### ③ `daily.html` 接上实时刷新

给它加了 `#freshness` 宿主 + `live.js`。现在「数据更新于 N 分钟前」那一行也会自己走。
`daily.js` 的 `renderFreshness()` 顺手画这一行（复用 `freshnessBarHTML`），并监听数据更新重拉整页
——**保住滚动位置**，用户可能正看到"哪些没抓到"的第 5 所学校。

### ⑤ 画像两套 UI 收敛（**顺带修掉一个静默的数据丢失**）

`onboard.html`（四行）和 `index.html`（完整表单）写的是**同一份 localStorage 画像**。

查的时候发现一个真 bug：`onboard.js` 保存时 `p2.majors = major ? [major] : []` ——
**只取第一个专业**。而匹配页允许填多个。于是：用户在匹配页填了「物理学、应用物理、力学」，
到画像页点一次保存，专业就剩「物理学」，**另外两个静默消失，用户不会察觉**。

修法：字段改成多值（逗号分隔），保存走 `splitList`。
实测：3 个专业 → 显示「物理学、应用物理、力学」→ 保存后仍是 3 个；额外字段（排名/英语/学位）全保住。

同时在代码注释里写清两页的**分工**（这里=首次填写四行，匹配页=微调全部字段），
免得下次又被当成"重复实现"删掉一边。
