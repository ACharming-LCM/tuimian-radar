# B（后端）第四十一场：首次运行自动建 state（B26）+ 清理 118 个用户

> 2026-10-19 17:05。交接阻塞：bundle 克隆出来的仓库没有 `server/var/state.json`，
> 第一次跑门禁红 5 条（`shutil.copyfile` 找不到文件）—— 接手的队友会以为项目坏了。

## ① 为什么新克隆会红

`server/var/` 在 `.gitignore` 里（运行时状态不进版本库），而门禁里有几条用例
把 `server/var/state.json` 复制到临时目录来造"演示身份"（`u_num_demo` 的画像）。
文件不存在 → `FileNotFoundError` → **第一次跑 5 红**。

## ② 改法：`load_or_seed`（不是"报错让人手建"）

| 入口 | 行为 |
|---|---|
| `StateStore.load(path)` | 文件不在 → **空状态、不落盘**（单元测试要的语义） |
| `StateStore.load_or_seed(path)` | 文件不在 → **建一份演示状态并落盘**（启动服务要的语义） |

`demo_state()` 只预置两个身份：

- `u_demo`：免费身份（付费墙演示用）；
- `u_num_demo`：**已订阅 + 完整画像**（推送/匹配/套磁信演示，门禁性能用例也靠它）。

九个顶层键一个不少：`version / users / posts / orders / counters / watches /
audit / profiles / pushes`。**绝不把开发机上那 118 个测试用户抄进去。**

接上的地方：`create_app()` 默认 state 改走 `load_or_seed`（所以 `uvicorn
server.app:app` 直接起也会建）；`run.py` 起服务前显式调一次并打印
"首次运行：已生成演示状态（u_demo / u_num_demo）"。

门禁侧：原来复制仓库 state 的 3 个性能用例改成**在临时目录用 `load_or_seed`
现建**（比复制更干净，也不会把开发机的测试用户带进性能测量）；
`check_push_targeting.py` / `measure_push_volume.py` 两个脚本同样改了。

```

清掉：116 个用户账号、12 份画像、10 条关注
```

- **帖子 / 订单 / 审计没动**：它们是演示内容（论坛三帖）和钱相关的记录，
  "清测试用户"不等于"抹掉站点内容"。
- `orders` 里 2 条属于演示身份，保留。
