# 推免雷达 · 商业计划书（BP）

> 一句话：**把散落在 29 所高校官网的推免公告，变成每天 10 条「今天该看、为什么、还剩几天」的推送，每条都能点回原文。**
>
> 交付物：Demo 演示（`DEMO-SCRIPT.md` / `Demo.pdf`）· GitHub 仓库 · 魔搭创空间部署链接
> 版本：2026-10-19

---

## 一、问题：信息不是没有，是「不知道今天有没有该我动作的事」

对准备推免（保研）的本科生来说，真正的成本不是"查资料"，而是**漏掉一条有时限的通知**。

- 公告散在 29 所学校的**研究生院 + 院系**官网，格式各不相同，很多招生细则只发在学院栏目里。
- 截止日经常藏在附件 PDF 里；有的公告干脆不写截止日。
- 微信群、公众号、二手 App 的信息无法核对，**不知道它是不是原文、是不是最新的**。
- 现有工具解决的是"聚合"，没有解决"**这条跟我有没有关系、我该不该今天动作**"。

**用户要的不是更多信息，是一个可以信任的"今天看这 10 条"。**

## 二、产品：一个说得清「哪里不知道」的监控工具

### 2.1 用户看到的三步

1. **填四行画像**：本科院校 / 专业 / 意向学校 / 意向方向。
2. **收到今天的推送**：约 10 条，按「学校 × 专业 × 方向 × 新鲜度」排序，每条给出「为什么推给你」和「还剩几天」。
3. **点开核对**：每条都能跳回学校官网原文；导师匹配可以复制邮箱；套磁信带 4 条**可回链**的公告引文。

### 2.2 三个别人没有的设计

| 设计 | 说明 | 为什么重要 |
|---|---|---|
| **字段三态** | `found`（读到了）/ `absent`（学校确实没写）/ `unknown`（我们没读到） | 不把"我们没读到"说成"学校没写"，用户不会因为一句"无截止日"而错过报名 |
| **引文可回链** | 套磁信每句话都能点回公告原文 | 防编造；接入模型后仍然成立 |
| **推荐可解释** | 每条推送都写「意向学校命中 / 方向命中 / 发布时间 / 截止紧迫」 | 用户能判断该不该信，而不是看一个黑箱分数 |

### 2.3 首屏质量控制（实测做过的事）

- `catalog`（目录/简章，285 条）收进「参考资料」，不占首屏推送位。
- `emba`/在职项目对学术型画像硬排除。
- 标题写明「报考点 / 网上报名」的统考事务公告，即使正文抽错成"推免"，也不进推免学生的首屏（本次修复 471 条）。
- 招生年份早于目标入学年的往届通知（如「2025 级选拔」）不进首屏（本次过滤 252 条）。
- 空的时候明确说「今天没有招生类公告」，**不拿讲座凑满一屏**。

## 三、数据与实测（2026-10-19 22:00 现算）

| 指标 | 数值 |
|---|---:|
| 公告入库 | 2561 条 |
| 默认展示（拒收 junk） | 2419 条 |
| 覆盖学校 / 单位 | 29 所 / 34 个院系单位（配置 37 个站点） |
| 招生通知 `announcement` | 512 条 |
| 参考资料 `catalog` | 285 条 |
| 截止日三态 | found 728 / absent 1167 / unknown 666 |
| 截止日明确且未过期 | **36 条**（7 天内 18 条） |
| 导师 | 557 位（327 位有邮箱，379 位有研究方向） |
| 自动检查 | 232 条契约门禁，0 失败 |

**漏抓对照**：北大 / 川大 / 清华物理三所用外部对照法验证，漏率从 74.1% 降到 **17.4%**。其余 26 所尚未验证——这是我们写在 PPT 里的边界，不假装覆盖全部。

> 口径说明：不报"覆盖 37 所学校"，报"29 所学校 / 配置 37 个站点"；不报"实时"，报"约 2 分钟一轮增量、30 秒内可见"。

## 四、市场与用户

- **目标用户**：大三下—大四上、正在准备推免的本科生；真实使用场景是手机。
- **市场规模**：全国具有推免资格的高校三百余所，每年推免名额在十几万量级（公开口径，具体以各校公示为准）。我们优先服务**信息最分散、院系公告最多**的 29 所。
- **付费动机**：一次报名/材料截止的错过，代价远大于一个月 29 元。

### 商业模式

| 收入 | 定价 | 状态 |
|---|---|---|
| C 端订阅 | ¥29 / 月：全部推送 + 匹配排序 + 套磁信 + 关注提醒 | 演示版为**模拟支付**，未接真实通道 |
| 免费层 | 每天前 10 条推送可见，原文链接永远免费 | 已实现 |
| B 端（规划） | 院系招生宣传数据服务 / 结构化公告 API | 未开始 |
| 数据服务（规划） | 按学校/学科订阅的公告变更流 | 未开始 |

**成本结构**：单个 29 校增量轮约 2 分钟；全量轮 16–60 分钟；单机即可运行，云资源成本低。主要成本是**规则维护与逐站对账**，这也是壁垒。

## 五、落地计划

| 阶段 | 时间 | 目标 | 关键动作 |
|---|---|---|---|
| **验证** | 0–3 个月 | 100 名真实推免生试用 | 补邮件提醒；找 3 所以上高校做漏抓对照；记录"因为推送而及时报名"的案例 |
| **扩张** | 3–9 个月 | 100 所高校 / 1 万用户 | 扩校流水线；微信服务号；付费转化实验；导师库扩展 |
| **商业化** | 9–18 个月 | 收入验证 | 院系合作、数据 API、机构版；把"可核对"做成品牌 |

> 当前处在**验证阶段的起点**：产品能跑、能演示、有 232 条自动检查，但**还没有真实用户试用数据**。这是下一步最重要的事。

## 六、竞争与壁垒

| 对手类型 | 他们的做法 | 我们的差异 |
|---|---|---|
| 保研 App / 公众号 | 二手聚合、经验帖、广告 | 每条回原文；三态；可核对 |
| 微信群 / 学长学姐 | 人工转发 | 29 校 × 37 站点持续监控；不漏公告 |
| 通用搜索引擎 | 关键词检索 | 按画像筛、按截止日排序、主动推送 |
| 大模型问答 | 生成式回答 | 不生成事实；引用可回链；不编日期 |

**壁垒不在模型，在数据管道与口径**：

- 37 个站点的栏目发现、翻页、附件解析、去重、事件流。
- 三态口径与逐站对账方法（漏率可复算）。
- 232 条自动检查，保证"改一处不会悄悄弄坏另一处"。

## 七、风险与边界（主动写在前面）

| 风险 | 现状 | 应对 |
|---|---|---|
| 覆盖不全 | 29 所，仅 3 所验过漏率 | 先做深 29 所，再扩校；对外只说已验证的数字 |
| JS 渲染页面 | 上海交大详情页抓不到 | 规划浏览器预渲染；当前明确标注"正文未读取" |
| 扫描版 PDF | 无 OCR，13 条附件读不出 | 标注 unknown，引导点原文 |
| 通知渠道 | 只有站内红点 | 邮件通道 1 周可做；微信需备案 |
| 合规 | 只抓公开页面、礼貌间隔、不绕验证码 | 公开仓库只放脱敏数据；名单类正文部署版隐去 |
| 付费意愿 | 未验证 | 先做免费试用与访谈，再谈定价 |
| 鉴权 | 单一共享口令，不是账号体系 | 公开演示版演示身份只读；正式版需会话/角色 |
