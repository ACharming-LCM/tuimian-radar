## 2. 沟通机制（不按这个来会打架）

1. **`contracts/` 是唯一接口。** 改形状先改契约，再改代码。契约改动记 `contracts/CHANGELOG.md`。
2. **AI 之间靠文件沟通**：`journal/<日期>-<谁>-*.md` 是留言，`issues/NNN-*.md` 是待决策。
   **做完事就写一篇 journal**，写清"做了什么 / 怎么验的 / 卡在哪"。
3. **`fixtures/` 让三方离线工作**：C 靠它写前端，B 靠它测接口。
   **数据一看就变，必须 `python tools/make_fixtures.py --as-of <日期>` 重出，否则别人的门禁会红。**
4. **`git add` 要指名道姓**，绝不 `git add -A`（会提交别人的半成品）。
   **不要重排别人文件的格式。**
5. **commit message 必须走文件**：`git commit -F <file>`。
   直接在命令行里写带引号/方括号/`<` `>` 的中文，PowerShell 会报 `ParserError`。
6. **并发警告**：用户会同时跑别的 agent。**动手删改前先重新列目录**，只动自己建的文件。

## 4. 数据层现在是怎么工作的

### 4.1 公告链路

```
sites.json(站点配置) → discover.py(找栏目) → listparse.py(解列表) 
→ detail.py(解详情) → pdf.py(解附件) → fields.py(抽字段) 
→ diff.py(变更检测) → crawl.py(组装) → data/out/notices.jsonl
```

**入口**：`python crawl.py --details 4`（全量约 10 分钟）。
`--only <单位名子串>` 只跑一个；`--refresh` 忽略缓存。

**产物**（都在 `data/out/`）：
`notices.jsonl`（唯一真相）、`changes.json`、`digest.md`、`coverage.md`、
**`freshness.json`（给 B 的 `/api/freshness` 用，形状是我定的，见 §5）**、
`faculty.jsonl`、`history/`、`runs/`。

### 4.2 ⚠️ 「截止日 31%」别再当 KPI 追

我量过：未抽到截止日的 136 条里，**精确正则只命中 9 条**（而且大多是学位审核、竞赛、
毕业论文这类**根本不是招生**的通知），其余 **127 条根本没有截止日表述**。

**所以 `null` 大多数是对的，不是失败。** 这个指标把"公告里没有"和"我们没抽到"混成一个数。
真要报，该报的是「**在有截止日的公告里抽到了多少**」——
而这件事的正确做法是给每条的字段加**三态标记**（见 §6 给 B 的第四条链）。

### 4.3 导师链路

`faculty_sites.json`（**手工配置的院系 URL**）→ `crawl_faculty.py` → `faculty.jsonl`

**四条解析路径，按优先级，第一个非空的赢（这样基线永远不会动）**：

| 路径 | 判据 | 来自哪个院系 |
|---|---|---|
| A | `li` 里挂 `h3` | 浙大物理（基线）、大连理工 |
| B | 表格**有表头**，按列名映射 | 复旦物理 |
| C | 姓名与职称**粘连无分隔符** | 浙大材料 |
| D | **内容区人名链接，判据是 href 指向个人页** | 浙大航空航天、北大化学 |

**⚠️ 导师层是"手工配置"的能力，不是泛化能力。**
换一所学校不能自动跑。**PPT 上不能说"支持多校导师"**，只能说
"已跑通 6 个院系（浙大物理/材料/航空航天、复旦物理、北大化学、大连理工）"。

### 4.4 变更检测的三分类（**别把这三个混起来**）

- `added` —— 学校新发的
- `changed` —— **学校改了内容**（正文变了且抽取器版本没变，或附件 URL 集合变了）
- `reparsed` —— **我们改了抽取代码**，不是学校改了通知

**`reparsed` 绝不能进用户提醒**（B 的 `/api/digest` 已按这条实现）。
混进去等于天天骗用户"学校更新了"。

## 7. 我是怎么反复栽的（**这一节最值钱**）

下面每一类我都栽过 **2 次以上**。请把它们当成检查清单。

### 7.1 「今天的数据刚好装得下 N 页」

**栽过 5 次。** 测试断言绑了"当前磁盘上恰好是什么数据"：
额度状态文件残留 / 断言绑学校名 / 断言"现在磁盘上是空报告" / 硬编码页数。

**正确做法**：绑**结构 + 不变量**，或者循环取到 `total` 为止，或者**自己造数据**。
（B 的门禁里曾有两条因为这个红：导师数据 67→259 涨了，硬编码 `2 页 × 50 = 100` 就不够了。
正确修法是循环取全再断言，**不是把 50 改成 100**。）

### 7.2 「同一个策略写在两个地方，迟早分叉」

**栽过 4 次**，而且每次都是**我改了副本没改原件**：

- `make_fixtures.py` 的排序口径没跟上服务端的两级排序 → fixture 与接口顺序只重合 26/50
- `_li_card_people` 里留着一份自己的 title 逻辑（老的首个命中），`_make_rec` 改成取最长命中后，
  大连理工的「助理研究员」照样显示成「研究员」
- fixture 的字段清单漏了 `relevance` → 排序按"缺失=1"算，真数据是 2
- 契约例子里写 `"subject": "【推免咨询】关于…的申请咨询"`，
  那个 `…` 是**举例省略**，我的生成器读成了"要截断"，B 按不截断做 →
  **测试红在了两边都没做错的地方**。**举例里的省略号必须写明"这是省略"。**

### 7.3 「一个判据只在部分站点上出错时，最容易瞒过去」

**栽得很惨的一次**：为了配"文章不是栏目"的反向闸，我写了 `/\d{5,}/`
（想当然："长数字就是文章 id"）。**可维普 CMS 的栏目 URL 就是 5 位栏目号**（`/50916/list.htm`）。
浙大材料那一页 **136 个栏目全被这道闸杀掉**，该站记录 **6 → 0**。
别的学校没炸，只因为它们的栏目名是字母（`/ysjs/list.htm`）。

**是靠"逐站点前后对账"抓到的** —— 我跑了全量、对比每个站点的条数，才发现有个站掉到 0。
**所以：改任何一个过滤器，都要跑全量并逐站点对账，不能只看总数涨了。**

### 7.4 「在"生成候选"阶段就失败的过滤器，不会在"拒绝原因"里留下痕迹」

`discover_boards` 有一道 `LIST_HINT` 只认维普/正方的 URL 形状。
上交/清华/川大这些站的栏目是**路径式、没有扩展名**的 → 候选在算分之前就被全筛掉。

**后果的隐蔽处**：`with_rejected=True` 里**拒绝数是 0**，报告看起来像"这些站点没有栏目"，
而它们首页上的招生类链接其实有 **149 个**。

**教训：报告"我拒绝了什么"是不够的，还要报告"我根本没生成候选"。**

### 7.5 「差一个字就漏」

`BOARD_NEG` 里本来有「党建」，而清华物理系的栏目叫「**党团**学工」——
差一个字没匹配上，于是党建/工会新闻被抓进来 3 条。

**否决词要覆盖同一个意思的常见写法**，不然就是"差一个字就漏"。

### 7.6 「一条脏数据同时打红两条门禁，报出来像两个问题」

那 3 条党团新闻的列表页**不带日期** → `publish_date` 是 `None` →
① 违反 schema（要求 `string`）② B 的排序测试直接崩（`str` 与 `None` 不可比）。

**根因只有一个。** 所以：**遇到多条门禁同时红，先怀疑共同根因，别分头修。**
现在 `publish_date` 缺失一律给空串，并有一条数据门禁不变量钉着
（**反向验证过**：故意塞一条 `None` → 立刻红）。

### 7.7 「排序键和展示字段抽错，比一个字段缺失严重得多」

**这是最近一次，也是最严重的一次。** 南开一条通知：

```
页面真实发布日  2026-04-13   （URL 是 /2026/0413/，页面上也写着）
我们存的值      2026-05-14   ← 正文里「材料审核结果发布时间：2026年5月14日前」
```

根因：`detail.py` 里 `发布时间：` 标签没匹配上时，回退成"在整块 head 里抓第一个像日期的"，
而 `HEAD_XP` 在某些模板上会框进正文。

**为什么比截止日严重**：`publish_date` 既是**排序键**又是**展示字段** ——
等于给用户看了个错日期。**而且它反向害了截止日**：截止日要求 ≥ 发布日，
发布日被推后 31 天，正文里 `2026-04-28` 的报名截止就被噪声闸**正确地**拒掉了。
**一个错字段把另一个正确字段拖下水，报出来却像"截止日抽不到"。**

**修的时候我又踩了一个**：把正则放宽成裸 `时间[：:]`，
结果匹配上「**截止**时间：2026年4月28日」，把报名截止日当成了发布日。
**放宽一个正则时要顺手问一句：它还能匹配到哪些我不想要的东西。**

最终优先级：**页面标签 → URL 内嵌日期 → 正文前 400 字的标签**。

**这里有个可复用的方法：找"数据自带的对照物"。**
维普系 URL 里就写着 `/YYYY/MMDD/`，天然基准。
用它量：旧 88.5% → 最终 **98.1%**（52 条基准里 51 条一致）。

**⚠️ 量的时候我也错了两次**：第一次只比 `detail` 单干的结果，
忘了真实记录是 `detail 日期 or 列表页日期`，报出"99 条丢失日期"的假象。
**先想清楚"我在比什么"，再去比。**

那一节完整记录：`journal/2026-10-17-A-发布日抽错与字段三态.md`

## 8. 硬规矩（违反会出事，不是风格问题）

1. **绝不编造截止日。** 抽不到就 `null` + 警告。**编造的截止日比 null 危险得多**
   —— 用户会照着一个假日期安排。
2. **`relevance` 只用于排序，绝不用于隐藏。**
   一个不可靠的相关性信号可以给结果**排序**，但永远不能**藏掉**结果。
   顺带：**API 的列表项故意不返 `relevance`** —— 不在载荷里，前端就没法拿它当筛选器，
   这条规矩被**结构性地**锁死了。**别好心把它加回响应。**
3. **绝不编造导师。** **一条假导师比少一条真导师严重得多。**
   这就是为什么复旦表格里 6 行错位的被丢掉、浙大材料报 61/66 而不是 66/66。
4. **失败必须带原因。** 所有失败路径都要能分类（`fail_tls_handshake` 这种），
   否则永远查不清。"解析失败"四个字等于没写。
5. **宁少不假。** 名录级数据（大连理工 233 人 / 方向 42%）不许并进匹配级数据假装覆盖率。
6. **说了做不到的事要在文档里写出来。** 半成品配诚实的说明，比假装做完强。
