## 三、结论（可以直接对外说）

1. **"漏"主要集中在两个可调的上限，不是解析坏了**：
   详情上限（北大 59、川大 53）与翻页（川大 101）。把 `--deep` 用上，
   这两块能立刻收回大头；`--deep` 实测代价是全站多 ~20 分钟（见 A10 journal）。
2. **川大还有 113 条是"太老被过滤"**：这是设计选择（产品卖"今天该看的"），
   不是缺陷。如果要做"历史全量库"，得单独跑一次 `--deep --max-stale-days 0`。
3. **清华物理系的 0 产出不是我们的锅**：那个公告栏 19 条、最新一条 400 天前，
   属于"栏目名对、内容停了"。这条要写进 0 产出站的解释里。
4. **仍然测不出来的**：首页发现不到的深层栏目、需要登录的、纯 JS 的页面。
   所以"212 / 302 / 19"是**下限**，不是"官网真实全量"。

> **这三所是抽样，"官网可发现"是我们能发现栏目 + 8 页以内的下限，不是官网全文。**

### ⚠️ 两个容易混的"抓到"：库里记录数 ≠ 这三栏对上的数

A18 的增量表是"**库里记录数**"：浙大 48→212、北大 179→323、川大 31→265、清华 12→75、上交 0→54。
而这张对照表的"改造后抓到"是"**在这三所学校的这三个招生栏目里、按 URL 对上的条数**"：
北大 **155** / 川大 **266** / 清华物理 **19**。

**两者不是一回事**，举例：北大库里 323 条，但其中包含物理学院等其它单元；
落到「研究生招生网」这个栏目、且能和官网条目对上的是 155 条。

⛔ **对外只说对照表这一列**（155 / 266 / 19，合计 440，漏率 17.4%）——
把"库里 323 条"当"抓到 323 条"会得出"北大超额 152%"这种说不通的结论。

### 填表规则（照这个填，别自己另算）

```
漏率 = 1 − 改造后抓到 ÷ 官网可发现
```
- **分母永远是"官网可发现"**（212 / 302 / 19），不是改造前的抓到数 ——
  拿改造前当分母会算出"改进了但漏率不变"这种自相矛盾的结果。
- 改造前漏率 = 1 − 138 / 533 = **74.1%**（这个数可以现在就写在一句话里）。
- 「改造后抓到」必须是**同法复测**的数：同栏目筛选、同 8 页、同 URL 去重。
  口径变了要在下面注明，否则前后两列不可比。

### 三条读表时要注意的

1. **清华物理系改造前是 0，改造后大概率还是 0** —— 它只有一个「公告」栏、19 条，
   **最新一条也在 400 天前**，放开配额救不回来。如果复测后不是 0，说明栏目发现逻辑变了，
   要在表下写清是哪一步变的。
2. **川大的大头是"翻页没到"（101 条）+ "太老被过滤"（113 条）**。
   8 页能收回前一半；后一半属于 `max_stale_days=400` 的设计选择，
   **除非同时用 `--max-stale-days 0`，否则这 113 条不会回来**。所以川大的漏率不会掉到 0，
   掉到多少取决于这两件事做到了几件。
3. **北大的大头是"每栏只解析 30 个详情"（59 条）+ "详情失败"（32 条）**。
   详情上限提到 60 能收一部分；"详情失败"那 32 条要另修（JS 渲染 / 无正文），
   **不是配额问题**。
