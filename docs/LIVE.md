# 实时刷新（`web/assets/live.js`）

> 2026-10-17 由智能体 C（前端）产出。用户这一轮的目标：**实现实时刷新**。
>
> 这个文件**独立存在**，一处都没碰 `common.js` / `style.css`。
> 理由不是洁癖，是协作现实：同一时间有别的 agent 在改那两个文件（D 派的鲁棒性五环）。
> 对 `common.js` 只做**只读调用**，调用失败就降级，绝不 throw。
> 页面上只加一行 `<script src="assets/live.js">`。

---

## 1. 一句话：这里说的"实时"是什么，不是什么

**不是**把抓取频率提到分钟级 —— 公告不是股票，学校一天发一次是常态，
把轮询提到分钟级只是对别人的服务器不礼貌，而且并没有让用户看到任何真东西。

**是**两件事：

| | 之前 | 现在 |
|---|---|---|
| 「数据更新于 27 分钟前」 | 一个**死数字**。打开半小时还写着 27 分钟前 —— 那是一句谎话，且最容易被评委一句话戳穿 | 每 15 秒本地重算，自己往前走 |
| 后台抓了一轮新的 | 用户不知道，除非自己去按 F5 | 30 秒内主动告诉他：「后台刚更新了数据　这页上还是旧的」+ 一个刷新按钮 |

## 2. 怎么工作

```
每 15 秒  ──→ 重算「现在多旧」，改写那行字（跨分钟时闪一下颜色，看得见它在动）
每 30 秒  ──→ GET /api/freshness，比较 generated_at
                 变了  → 重渲染新鲜度块 + 挂提示条 + 发 tuimian:data-updated 事件
                 没变  → 用后端刚算的 age 校准一次（本地推算跑久了会漂）
切到后台  ──→ 暂停轮询（手机省电）
切回来    ──→ 立刻补探一次（不是等下一个 30 秒）
```

### 2.1 时间怎么算（这一条有坑）

```
current_age = 后端算好的 generated_age_hours + (现在 - 取到它的时刻)
```

**不是** `now - generated_at`。因为演示机和服务器的时钟可能差几分钟，
那样算出来会是**负数**（"数据来自未来"）—— 负数比不刷新更难解释，
而且它会在评委面前出现两次（首页一次、列表页一次，两个数字还不一样）。

以后端给的 `age` 为基准往前推，永远不会是负的。

### 2.2 为什么"数据变了"不自动替换列表

**用户可能正在读某条、正在筛选。** 内容自己跳变会让人失去"我刚才在看哪"的位置感。

所以是提示 + 按钮，由用户决定什么时候换。
而按钮做的是 `location.reload()` —— 不是我从外面替页面改 `#results`：
页面自己的状态（筛选、排序、滚动）它自己知道怎么还原，我替它改反而会破坏它内部的 state。

> 这也是一种克制：**"实时"要的是"不用按 F5 也知道"，不是"内容自己乱跳"。**

### 2.3 三个参数

| 参数 | 值 | 为什么 |
|---|---|---|
| `TICK_MS` | 15000 | 相对时间的节拍。更短没意义（分钟级显示，15 秒足以跨过边界） |
| `POLL_MS` | 30000 | 问接口的节拍。本地服务，30 秒一次无压力；演示时也够灵敏 |
| `API_TIMEOUT_MS` | 6000 | 轮询失败**必须静默**，这是后台动作，不该弹错误 |

## 4. 怎么验证（可复现，不用等半小时）

```powershell
cd C:\Users\<user>\OneDrive\文档\deepseek-harness\default-workspace
$env:CDP_PORT='9333'
# 需要 8001 在跑
```

**验「时间真的在走」**：把本地"取到数据的时刻"往前推 25 分钟（越过整点边界），看文字变不变。
`5 小时前` → `6 小时前` 就是它在走。**推 10 分钟是看不出来的**（round(5.26)=5、round(5.43)=5），
这一条我第一版就误判过。

**验「数据变了会提示」**：地址里加 `&live=test`，然后

```js
TuimianLive.simulateUpdate()   // 伪造一次 generated_at 变化
```

2 秒内 `.fb-new` 应该出现。**`live=test` 是硬门槛**，防止演示时误触。

**验「轮询真的在跑」**：等 35 秒，看 `TuimianLive.state.fetchedAt` 有没有往后跳 30 秒。
（实测过：29 秒。）

**验「页面上真加载了」**（而不是我动态注入的）：
看 `typeof window.TuimianLive === 'object'` 且没手动注入过。

## 5. 验过的（CDP 实测）

| 项 | 结果 |
|---|---|
| 时间走动 | 推 25 分钟 → `5 小时前` 变 `6 小时前`（`textChanged: true`） |

| 加载方式 | 三页（notices / index / 375 手机）`viaHtmlTag: object`、`started: true` |
| 数据源如实 | 页脚写「接口 /api/freshness」 |
| 横向溢出 | 三页全 0 |
| 手机触控 | 刷新按钮 105×44、关闭按钮 44×44（≥44） |

### 修过的一个 bug

第一版 `poll()` 拿到 `/api/freshness` 的原始响应就交给渲染器，**没标来源**，
于是页脚写成「文件 data/out/freshness.json」—— 明明是从接口拿的。
**数据源说谎是这个项目最不能犯的错**，而这里差的只是一个 `data.from = 'api'`。

## 6. 一个协作事故（值得全项目记）

这一轮我的 `live.js` 写好后**"消失"了一次**。不是被删：

```
14:34:02  checkout: main → wip/subagent-round2
14:34:03  commit 3b2077f  "WIP: 我（A）开的 subagent 第二轮的半成品，未验收，勿并入 main"
14:34:04  checkout: wip/subagent-round2 → main
```

**`git checkout` 切分支时会带走工作区里未提交的文件。** 于是我的 `live.js`
（还有那个 agent 的 `drift.js` 和全部未提交改动）被卷进了那个 WIP 提交，切回 main 后就"不见了"。

从 `3b2077f` 单独捞回来了：
```powershell
git checkout 3b2077f -- web/assets/live.js
git reset -- web/assets/live.js      # 取消暂存，让它回到未跟踪
```

> **教训：在这个多人共用工作区的环境里，未提交的成果随时可能被别人的分支切换带走。**
> 写一段就提交一段，比"等全部做完再提交"安全得多。
> 这一轮我捞回来之后第一件事就是 `git add` + `commit`，没有再等。
