## 二、字段可信度三态（这是产品的差异化，重点页）

`field_state` 给每个字段三档：`found` 抽到了 / `absent` 正文读到了确实没有 / `unknown` 我们判不了。

| 字段 | found | absent | unknown |
|---|---|---|---|
| `deadline`（截止日） | **772** | **1233** | **746** |
| `majors`（专业） | **1920** | **492** | **339** |
| `attachments`（附件） | **738** | **1381** | **632** |
| `body`（正文来源） | ok **1790** / generic **507** / missing **454** | | |

### 截止日这组数字怎么讲（**最容易被问的一页**）

**❌ 不要这么说**：「截止日抽取率 28%」（772 / 2751）。
那是把「公告里本来就没有」和「我们没读到」混成一个数。

**✅ 应该这么说**：

> 2751 条公告里，**772 条明确给出截止日，我们全部读到**；
> **1233 条正文通篇没有截止日表述**（宣传册、名单公示、讲座通知这类）；
> 剩 **746 条我们判不了**（正文兜底抓 / 太短 / 扫描件 / 页面被截断）——
> 这 746 条在界面上显示「未能读取截止日，请点原文核对」，**不会说成"没有截止日"**。

**`unknown` 占 27.1%（746 / 2751）**：四分之一强的公告我们不知道它截止了没，
压掉就等于替用户做了个我们没有依据的决定。

### 一个必须知道的口径：772 条 found 里 735 条已经过期

实测（基准日 2026-10-18）：**772 条读到截止日的公告里，735 条已经过了，只有 37 条还有效。**

这是**公告跨度 16 年**的必然结果（最老 2010 年）。所以：

- **归档页看到「已过期」徽标是正常的**，那是我们诚实标出来的；
- **别把 772 说成"772 条机会"**，能说的是「772 条读到截止日，其中 **37 条今天还没过**」。

### 为什么 `unknown` 这一档值得单独讲

> **「我们宁可说'不知道'，也不说'没有'。」**
> 「这公告没写截止日」和「我们没读到截止日」对用户是**相反**的两句话。

### `junk` 是什么（168 条，**不删，只标**）

| 依据 | 条数 | 意思 |
|---|---|---|
| `body_lt_100` | 141 | 正文不到 100 字，基本是空壳 |
| `body_meta_only` | 97 | 正文只有标题/时间/导航，没有实质内容 |
| `body_is_index` | 12 | 招生目录索引页（标题是院系名、正文是院系导航；判据还细分到 `table:N`） |
| `title_is_site_name` | 11 | 标题就是站点名（"XX大学研究生招生网"）—— 典型栏目页 |
| `body_nav_list` | 2 | 正文是一串链接 |
| `body_numbered_nav` | 1 | 标题=三位编号+院系名、正文是编号导航 |

（A21 之后 junk 从 170 降到 168：2 条「table 目录页」被救回，`title_is_site_name` 也少了。）

一条可能命中多个依据，所以加起来大于 168。

**为什么不删**：删了就没法回答"你们是不是漏了某校的公告"。保留 + 标记，
才能在页面上说「这条收进来了，但它是空壳，暂不作为推荐」。

### 一句话版本

> 「我们入库 **2751 条**、默认展示 **2583 条**（另外 168 条是空壳，不占推荐位），

> **同一个窗口两边必须传同一个 `days`**，否则 8~30 天那批会同时出现在两边。

### ⚠️ 「今日更新」页现在是一份**陈旧快照**（20:14 实测）

`/api/changes` 的 `generated_at` 停在 **16:43**（1135 条时代），而 `notices.jsonl` 已在 **20:17** 变成 2751 条 ——


- ⛔ **别用它讲"今天新增了多少"** —— 它既不是 2751，也不是今天的增量（已报 A，数据侧修）。
- ✅ 要讲"数据在更新"，用**页头心跳**（`/api/health/data`：2751 条、最近 24 小时 7 轮）；
  要讲"今天该看什么"，用**推送页四档**（`/api/updates` + `/api/library`：10 / 27 / 112 / 2647）。

### 📌 这一节唯一的硬规矩：改数字必须改「取数时刻」

本文开头那一行 **`取数时刻 + HEAD` 是这套数字的一部分**，不是装饰。踩过四次：

- `93a4686/01:10` 那版被 A 的 `5ccdcc9` 作废（unknown 293 → 284）；
- `7849bdf/02:11` 那版被 A1–A3 作废（1119 → 1120）；
- `1a25222/13:20` 那版被 A14/A14b 作废（junk 77 → 90 → 84）；

所以顺序必须是：**所有人提交完 → `git rev-parse --short HEAD` → 重跑脚本 → 改数 → 写时刻**。
而且**派生量必须一起重算** —— 改头部不改派生，是上一轮被抓到的 5 处对不上的原因。
