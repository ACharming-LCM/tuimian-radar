# 导师层：数据可得性的边界在哪

> 2026-10-17 夜，A。这份文档记的是**摸站摸出来的结论**，不是计划。
> 每一条都写着"怎么验的"，所以可以复现，也可以推翻。

## 一句话结论

**导师数据的上限不在解析器，在"名册是否出现在静态 HTML 里"。**

已跑通的 5 个院系，恰好都是名册**静态可得**的；剩下卡住的全是同一类原因：
正文由 JS 加载，或者那个栏目本身就是空的。**再加解析路径解决不了这个** ——
我已经加到第四条（A/B/C/D），能覆盖的结构基本都覆盖了。

---

## 一、已跑通（324 人 / 5 院系 / 研究方向 87%）

| 学校 | 院系 | 人数 | 有方向 | 名册的静态形态 | 走的路径 |
|---|---|---|---|---|---|
| 浙江大学 | 航空航天学院 | 126 | 110 (87%) | `<a href="person…">陈伟球</a>` 按研究所分组 | **D** |
| 浙江大学 | 材料科学与工程学院 | 66 | 61 (92%) | `朱笑东高级实验师` 姓名职称粘连 | **C** + 二级抓取 |
| 北京大学 | 化学与分子工程学院 | 65 | 44 (68%) | `<a>张三</a>`（`/ktz/<缩写>/`） | **A/D** + 二级抓取 |
| 浙江大学 | 物理学院 | 50 | 50 (100%) | `li > h3` 卡片 | **A**（基线） |
| 复旦大学 | 物理学系 | 17 | 17 (100%) | 带表头的 `<table>` | **B** |

四条路径对应四种真实结构，都是被真实院系逼出来的，不是设计出来的：

| 路径 | 判据 |
|---|---|
| A | `li` 里挂 `h3`（浙大 `person.zju.edu.cn` 模板） |
| B | 表格**有表头**，按列名映射（姓名/职称/研究方向/邮箱） |
| C | 姓名和职称**粘连无分隔符**（`吴春春副研究员`）→ 姓名懒惰匹配、职称取最长命中 |
| D | **内容区里的人名链接**，判据是 **href 指向个人页**而不是 `list.htm` 栏目页 |

**路径 D 的判据值得单独记**：不能用"文字像人名"——那样会把「学院概况」「师资队伍」
算成人（评估报告里踩过：一个只 6 个人的页面被数出 38 个"人"）。
**按 href 分就够了**：实测浙大航空航天那页人名样式链接 191 个，127 个指向个人页、37 个指向栏目页。

## 二、卡住的：四种原因，逐个查过（**不是猜的**）

### 1. 浙大光电科学与工程学院 —— 栏目**本身是空的**

我先判成"JS 渲染"，**判错了**。把该站 22 个栏目 ID 全试了一遍：
`/72680` `/72681` … `/72715` 加 `list2` `list3`，带个人页链接的栏目全是**通知公告**
（那些"个人页链接"是文章页 `/page.htm`，不是老师）。
「师资概况」页 `/72682/list.htm` 的正文里**一个名字都没有**。

→ **这个院系的师资名册不在它的网站上（至少不在静态页里）。**

### 2. 浙大高分子科学与工程学系 / 能源工程学院 —— 正文 JS 加载

- `polymer.zju.edu.cn`：首页 3277 B，正文只剩页头页脚（中文网/办公网/ENGLISH/版权），带 `const HTMLFontSize = …` 的 JS
- `www.doe.zju.edu.cn`：2145 B，正文实际只有 `--> 浙江大学|能源工程学院`

**试过免依赖的预渲染**：`msedge --headless=new --virtual-time-budget=8000 --dump-dom`
→ 渲染后仍是 3271 B 空壳，**且 25 秒/页**。
（机器上有 Edge 155 和 Chrome 154。这条路对这两页无效，成本也不划算。）

### 3. 北大物理学院 —— 名册**不挂在首页导航上**，且目标页正文为空

首页 HTML 里「师资」出现 **0 次**。从「人才计划」页的导航里挖出了真实栏目：

```
教职员工   /zy_list.jsp?urltype=tree.TreeTempUrl&wbtreeid=1011
教研人员   /jsfcjy.jsp?urltype=tree.TreeTempUrl&wbtreeid=1658
工程技术人员 /jsfcgjs.jsp?urltype=tree.TreeTempUrl&wbtreeid=1659
```

**这三页每页约 30 KB，但个人页链接数 = 0**，最大文本块就是**左侧导航本身**
（`教职员工 教研人员 工程技术人员 院士 人才计划 …`）。正文是空的。

→ 苏迪/正方 CMS 的 `.jsp?urltype=tree.TreeTempUrl`，名册内容也是后加载的。

### 4. 中科大物理学院 —— 「师资队伍」下拉里没有名册

它的「师资队伍」是个 **空 href 的下拉父项**，子菜单只有 3 项：两院院士 / 博士生导师 / 教学名师。
而「博士生导师」页 `/2026/0414/c12975a726612/page.htm` 打开是 **通知列表**
（「物理学院2027年研究生招生博导信息」「书记院长值班表」），13 个"个人页链接"全是文章页。

→ 静态导航里**没有**师资名册这一项。

## 三、系统性路子：试过三条，都验了成色

逐校挖的边际收益在掉，所以转向"一条路子覆盖多校"。**三条都试了，结论如下。**

### 3.1 Tsites 平台的导师查询接口 —— **能拿到名录，拿不到方向**

**发现**：复旦 `supervisor.fudan.edu.cn`（「导师风采」）用的是 **Tsites** 建站平台的
高级搜索组件。从 `/system/resource/tsites/dsfcadvancesearch.js` 里读出了完整接口：

```
GET /system/resource/tsites/dsfcadvancesearch.jsp
    ?enrolleunit= &enrollid= &yjxk= &pageindex= &pagesize=
    &teacherName= &searchDirection= &dslx=
    &viewmode=8 &viewid=<页内变量> &siteOwner=<页内变量> &viewUniqueId=<页内变量>
返回 JSON
```

**实测（pagesize=200，共 31 页）**：

```json
{"totalnum": 6093, "totalpage": 31, "teacherData": [{
   "name": "艾剑良", "dslx": "学术学位博士生导师",
   "email": "teacher87@fudan.edu.cn", "researchdirection": "",
   "url": "https://faculty.fudan.edu.cn/aijianliang/zh_CN/index.htm",
   "enrolldiscipline": "航空宇航科学与技术" }]}
```

| 字段 | 填充率 |
|---|---|
| name / dslx（导师类型）/ url | **200/200 = 100%** |
| email | 197/200 = **98.5%** |
| enrolldiscipline（学科） | 198/200 = **99%** |
| **researchdirection（研究方向）** | **0/200 = 0%** ❌ |

而且 `faculty.fudan.edu.cn/<slug>/` 那些个人主页**返回 617 B 的错误页**
（Tsites 自带的 `tipmsg.css` 错误模板），去掉 `/zh_CN/index.htm`、加 Referer 都一样。

**裁定：这是"名录级"数据，不是"匹配级"。**
6093 位复旦导师的姓名 + 邮箱 + 学科 + 导师类型是真的、权威的、有用的（套磁需要邮箱），
**但没有研究方向，做不了"专业契合"匹配。**
所以**没有把它并进 `faculty.jsonl`** —— 那会把 87% 的方向覆盖率稀释成一个假的数字。
（真要进，应该另开一层、明确标成"名录级"。这是产品决定，不是数据决定。）

**杠杆也有限**：扫了手上 15 所学校的研招网/研究生院首页，
**只有复旦**用 Tsites（其余 tsites 引用 0）。

### 3.2 中科大「各学位点招生博导汇总表」 —— **是空白模板**

`gradschool.ustc.edu.cn` 上挂着一份 `.doc`（51 KB，OLE2 老式 Word）。
用 Word COM 打开：**192 段、1 个表格（26 行 × 7 列）**，
但内容是一张**没填的表**——「中国科技大学学位点　　年招生博导汇总表」，
`二级学科名称：` 是空的，表头只有「类别/姓名/校内/已聘博导/新聘博导」。

→ 是**待填的表格模板**，不是数据。（顺带：Word COM 用完要清 `WINWORD` 进程。）

### 3.3 「导师队伍」类栏目 —— 同一套模板，还没逐个验

武大 `gs.whu.edu.cn/xwgz/dsdw.htm`、华科 `gs.hust.edu.cn/xwgz/dsdw.htm`、
西安交大 `gs.xjtu.edu.cn/xwgz/dsdwjs.htm` 是**同名同构**的页面，哈工大有
`www.hit.edu.cn/sssds/list.htm`。**还没打开验过成色**，先记下位置。

## 四、所以下一步只有两个方向

1. **预渲染**：需要一个能真跑 JS 的浏览器，把名册页渲染后再解析。
   已知成本：`--dump-dom` 25 秒/页，且**对浙大高分子无效**（渲染后仍是空壳）——
   所以要先找一个**确认能渲染出内容**的页做验证，再决定值不值得做进去。
2. **换数据源**：找"名册以静态形式存在"的地方（学校发的汇总文件、研究生院的老式页面）。
   中科大那份是模板，但**这个思路本身还没穷尽**。

**两条都还没做。** 今晚的产出是把"卡在哪、为什么卡"钉死，
并且**没有为了凑数把名录级数据混进匹配级数据里**。
