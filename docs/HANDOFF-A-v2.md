## 2. 管道现在长什么样

【实测】入口是 `collector/tools/run_daily.py`，五步。
**耗时取最近几轮的范围**（不是单轮快照 —— 单轮数会随缓存命中率浮动）：

| 步骤 | 耗时 | 说明 |
|---|---|---|
| 抓公告 | **1200~1640s ≈ 20~27 分钟** | **这是大头** |

| **合计** | **28~34 分钟** | 取决于缓存命中率 |

**"跑一轮要半小时上下"是最容易被低估的一件事。** 你第一小时就该知道这个数。

【原文】缓存策略（`run_daily.py` 注释）：

> 师资名单一个月才变一次，每天 `--refresh` 纯粹是打学校服务器；

> （缓存命中很快），**每周单独跑一次带 `--refresh` 的**。

## 3. 坑（按危害排，全部来自 journal 原文）

### 3.1 一个自己不可信的指标，比没有指标更危险

【原文】`2026-10-17-A-导师泛化实测.md`：

> **教训（这是本轮最值钱的一条）**：一个自己不可信的指标，比没有指标更危险 ——
> **它会制造假结论。** 今晚踩了两次（另一次是"栏目精度 60%"，实测 31%）。

**这条的意思是**：你要是量了一个自己都不信的数，然后拿它去指导决策，
你会在错误的方向上"有条不紊"。**量任何东西之前先问：这个数我信吗？分母是什么？**

### 3.2 一个根因，多条门禁同时红

【原文】`2026-10-17-A-日更两轮与扩抓.md`：

> 根因只有一个：我把 `field_state` 写在 `rec.update({...})` 的**字典字面量里**，
> 而那个 `update` 在 `_make_rec` 里……**这正是交接文档里"多条门禁同时红先怀疑共同根因"那条的现实版。**

**遇到三条门禁同时红，先别分头修**，去找那个共同的根因。

### 3.3 数量没变、质量掉了（扩抓最隐蔽的形态）

【原文】`2026-10-17-A-日更两轮与扩抓.md`：

> 这是"网络不好 ≠ 数据变少"的导师版，而且更隐蔽：**数量没变，质量掉了**。

扩抓/改解析之后，**总条数一样不代表没坏**。要逐站点对账（v1 §7.3 那条），
还要看**字段级**指标（正文长度、方向填充率），不只看条数。

### 3.4 差点去"修"一个不存在的问题

【原文】`2026-10-17-A-新鲜度暴露27个死站点.md`：

> **差点去"修"一个不存在的问题。**

（那次是 fresh 的 `last_ok` 语义被误读——它被无条件写成"本轮时间"，
失败的学校也写。所以"27 个死站点"里有一部分是误判。）

**拿到一个异常数，先问它的语义**，别急着改代码。

### 3.5 "前排是宣传册" ≠ "排序没接 relevance"

【原文】`2026-10-17-A-派单给BC.md`：

> **教训**：我看到"列表前排是宣传册"就推断"排序没接 relevance"，
> **实际是这些通知的标题里就带"招生"二字，A 的 relevance 把它们判成了 2 档**
> （这是 C 报给我的走查 #5，我误判了整整一晚）。

**同一个现象的根因可能完全相反**：不是"排序没生效"，是"数据层把它们判成了高相关"。
**先看数据，再怀疑代码。**

### 3.6 差一个字就漏（否决词要覆盖同一意思的常见写法）

【原文】v1 §7.5：

> 差一个字没匹配上，于是党建/工会新闻被抓进来 3 条。

### 3.7 在"生成候选"阶段就失败的过滤器，不会在"拒绝原因"里留痕

【原文】v1 §7.4：

> `discover_boards` 有一道 `LIST_HINT` 只认维普/正方的 URL 形状。
> 上交/清华/川大这些站的栏目是**路径式、没有扩展名**的 → 候选在算分之前就被全筛掉。
> **后果的隐蔽处**：`with_rejected=True` 里**拒绝数是 0**，报告看起来像"这些站点没有栏目"。

**报告"我拒绝了什么"不够，还要报告"我根本没生成候选"。**

### 3.9 发布日抽错会连锁害截止日

【原文】`2026-10-17-A-发布日抽错与字段三态.md`：

> `publish_date` 在某些模板上会框进正文，于是正文里的日期被当成了发布日
> （南开那条：页面真实 `2026-04-13`，我们存了 `2026-05-14`）。
>
> **它为什么比缺截止日严重**：它既是排序键又是展示字段；
> **而且它反向害了截止日** —— 截止日要求 ≥ 发布日，发布日被推后 31 天，
> 正文里 `2026-04-28` 的报名截止就被那条噪声闸**正确地**拒掉了。

**一个错字段把另一个正确字段拖下水，报出来却像"截止日抽不到"。**
现在的优先级：页面标签 → URL 内嵌日期 → 正文前 400 字的标签。

## 6. 环境与命令

```powershell
$env:PYTHONIOENCODING="utf-8"          # 否则中文输出乱码
Set-Location D:\tuimian\collector

# 重出 fixtures（**改了数据必须跑**，否则 B 的门禁会红）
D:\python.3.10.11\python.exe tools\make_fixtures.py --as-of <今天>

# 重出事件流
D:\python.3.10.11\python.exe tools\make_events.py

# 你自己的测试（12 个文件，逐个跑）
foreach ($t in @("test_discover","test_deadline","test_match","test_diff","test_pdf",
                 "test_detail","test_faculty","test_data_contract","test_field_state",
                 "test_robustness","test_stability","test_events")) {
  D:\python.3.10.11\python.exe "tests\$t.py"
}
```

**必须知道的机器事实**：

- **Python 一律用 `D:\python.3.10.11\python.exe`**（会话自带那份**没有** PyMuPDF/pypdf）
- **PowerShell here-string（`@'...'@`）多次翻车**：反引号变反斜杠、中文括号被误解析。
  **长文本用 `write` 工具落 `.py` 文件再跑**，或者用 `edit` 改文件
- **`Set-Content -Encoding utf8` 会加 BOM**，破坏 `json.load`。**写 JSON 一律用 Python**
- **绝不给 `$HOME` 赋值**（只读自动变量，赋值静默失败）
- **`Remove-Item` 用 `$env:` + 通配符会被安全策略拦**，用字面完整路径
- **并发警告**：用户会同时跑别的 agent。**动手删改前先重新列目录，只动自己建的文件**

## 8. 你接手时最可能踩的三个坑（我根据今天的实际情况排的）

1. **改了数据不重出 fixtures → B 的门禁红，而红的原因看起来像"他的测试太严"**
   （v1 §10 记着"我害过 B 两次"）。**改了 `notices.jsonl` 就跑 `make_fixtures.py`**。

2. **`is_backfill` 的过滤位置**（A 特意写了一条"需要 B，这条不说清他会修错"）：
   补抓过滤**必须在截断到 limit 之前**。放错位置 → 前 20 条里只剩 1 条。
   B 已经修好了（`server/push.py` 第 ① 步），但你以后动事件产出时别把这个前提破坏掉。

3. **`run_daily.py` 里 `--refresh` 的取舍**：日更走缓存（快），每周单独跑一次带
   `--refresh` 的。**别为了"数据更新"就每天全量重抓** —— 那是打别人学校的服务器，
   而且会让个人主页缓存失效、二级抓取受上限约束。
