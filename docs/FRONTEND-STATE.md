## 0. 怎么造出这四种状态（可复现）

**没有改任何契约文件，也没有动 `server/`。** 四种状态是用一个桩服务造出来的：

```bash
# 仓库根目录（有 web/ server/ collector/ 的那一层）
python <工作区>/_c-states.py --port 8011 --mode empty     # 起桩
#   /__mode?set=empty|e500|timeout&fx=off|on|empty       # 运行时切状态
```

桩做两件事：像真服务那样把 `web/` 挂在 `/`（`server/app.py` 就是这么挂的，**只挂 web/**），
然后按模式决定 `/api/*` 的行为。

| 状态 | 怎么造 | 和真实情况的对应 |
|---|---|---|
| **正常** | 真接口 `http://127.0.0.1:8001/` | 演示当天的样子 |
| **空数据** | 桩 `mode=empty`：接口 200、形状完整、值全空 | 抓取还没跑完 / 某个学校 0 条 |
| **接口 500** | 桩 `mode=e500`：每个 `/api/*` 都 500，响应体是 `Internal Server Error` 纯文本（真崩溃就长这样） | 后端挂了 |
| **接口超时** | 桩 `mode=timeout`：每个 `/api/*` 挂起不返回 | 服务在跑但卡住 / 网络没断但不通 |

`fx` 开关控制 `/contracts/` 和 `/data/out/` 挂不挂：

- `fx=off` = **真服务的挂法**（`server/app.py` 只挂 `web/`）→ 接口挂了就**没有样例可以回退**
- `fx=on` = 从仓库根 `python -m http.server` 那种挂法 → 回退路径真的能走通
- `fx=empty` = 同上，但把 `contracts/fixtures/*.json` 换成程序生成的**空样例**
  （生成在仓库外，磁盘上的契约文件一个字节都没动）

> 这两个挂法差别很大，**是这次走查里最容易搞错的一点**：
> 在真接口服务上加 `?api=fixtures` 是**读不到**样例的（那个服务不挂 `contracts/`）。
> 页面上原来那句「想离线看样例就加 `?api=fixtures`」在真服务下是错的，已在第 3 节 #3 里改掉。

截图方式不是 `chrome --headless --screenshot`，而是 CDP 驱动
（`_c-cdp.js`）：固定等待 N 秒后截图，同时**量**出横向溢出、可见空态文案、控制台报错、
`undefined`/`[object Object]` 之类脏字。看不清的图会骗人，量出来的数不会。

| 首屏 3 秒看得懂「这是什么网站」 | 改后可以。首屏从上到下是：品牌「◎ 推免雷达 TUIMIAN RADAR」→ 导航 → `h1`「匹配结果」（等效 32px）→ 一句说明「全国高校的**推免 / 夏令营 / 预推免公告**聚在这里，按契合度排序……」 |
| 字号（3 米外） | 改前正文 15px、`h1` 27px，投屏偏小；现在 ≥1600px 视口整体放大 1.2 倍 → 正文等效 **18px**、`h1` 等效 **32px** |
| 容器宽度 | 改前上限 1240px，1920 屏右边空一大片；放大后等效 1488px |

做法是 `web/assets/style.css` 里一条 media query：

```css
@media (min-width: 1600px) { body { zoom: 1.2; } }
```

为什么用 `zoom` 而不是逐条改字号：页面里的字号全是 px（`14px` `12.5px` `13px`…遍布十几个选择器），
一条条写媒体查询既容易漏又容易和移动端那套打架。`zoom` 在 Chrome/Edge 里是做这个的标准手段，
演示用的就是 Chrome。副作用是 CDP 量到的 `computed font-size` 仍是 15px（zoom 不改计算值、改渲染），
所以上表写的是「等效」。

## 3. 发现的问题：改了的

一共 12 条，全部在这一轮改完并重新截图自查过。**按严重程度排。**

### #1 接口挂起时，9 个页面永远停在「正在读取数据…」🔴 最严重

`common.js` 的 `apiGet/apiPost` 直接 `fetch`，**没有超时**。服务在跑但某个接口卡住时，
页面就一直转，既没有报错也没有重试按钮 —— 台上遇到这个，演示直接死在半路。

改法：所有请求走 `fetchWithTimeout()`，接口 8 秒、样例 5 秒，用 `AbortController` 中断；
超时按「接口没通」处理（可以回退）；错误态给一个**「重试」按钮**和两个能去的页面。

> 这也是为什么不能用 `chrome --screenshot` 验这一态：挂起的请求会把 virtual-time 卡住，
> 截出来的可能是「请求其实已经回来了」的错图。

### #2 失败的时候，页脚在说谎 🟠

`#api-source` 的静态默认值是 `contracts/fixtures`（8 个页面里 7 个这么写）。
页面失败时 `markSource()` 根本没被调用，于是**一个什么都没读到的页面，页脚写着「数据源：本地样例」**。

改法：① `showError()` 里也调 `markSource()`，并新增一档「没读到（接口和本地样例都没通）」；
② 8 个 HTML 的静态默认值统一改成「读取中…」；③ 顺手删掉 `index.html` 里那句
「后端上线后只需把 `API_MODE` 改成 `'live'`」—— 早就是 live 了。

### #3 4xx 被当成「接口没通」🟠

`POST /api/letter` 对不存在的公告返回 **404**，`liveOrFixture` 却把它当成断线：
去回退样例（**拿样例冒充真数据**），失败后告诉用户「要么连不上接口，要么找不到样例文件」，
还建议你去跑 `uvicorn` —— 服务明明在跑。

改法：加 `isClientError()`，**4xx 不回退**（404 是答复、402 是额度，都不是断线）；
错误面板按状态码分流措辞：404 说「接口里没有这条数据」并解释 id 变更，402 指向订阅页。

### #4 500 的「底层报错」把真正的错因埋了 🟠

原来只显示样例文件的 404/500，**看不到 `GET /api/notices → HTTP 500`**。
改法：`liveOrFixture` / `loadChangesData` 把接口那一步的错误挂到样例错误上（`fxErr.liveError`），
面板**先报接口**，再列样例尝试。

### #5 匹配页空态是一句万能废话 🟡

原文案「这个分类下暂时没有记录。」放在哪个页面都成立，也就是哪都帮不到。
改法：区分两种情况 —— 一条都没有时说明**两个可能原因**（筛得太窄 / 库里还没有）+ 下一步；
有条目但当前分类为空时写明「共 N 条，换个分类看」。

### #6 详情页在真接口下说「在演示数据里找不到」🟡

`renderNotFound()` 不管数据源都用同一句。真接口下 404 的原因是**id 过期或抓取调整后 id 变了**。
改法：按 `dataSource` 分措辞，真接口下把「id 变更」这个真实原因写出来。

### #7 订阅页额度自相矛盾 🟡

接口没返回 `daily_free_quota` 时，账户行显示「额度 **0** 条／天」，
而同一屏下面的对照表写「每天 **3** 条公告详情」—— 同一个数字两个说法。
改法：缺字段时按 3 显示，并标一句「接口这次没返回额度字段，按 3 条／天显示」。

### #8 订阅页套餐为空 → 右列整块空白 🟡

`plans: []` 时右列一个字都没有，看着像页面坏了。改法：给一句人话，并指路不依赖这个接口的两块。

### #9 500 态下筛选下拉是空的 🟡

`renderToolbar()` 只在数据加载成功后跑，失败时三个 `<select>` 是空的。
改法：HTML 里先放「全部学校 / 全部单位 / 全部方式」占位。

### #10 每页一个 favicon 404 🟢

控制台每条页面加载都有一条 `404 (Not Found)`。改法：9 个页面加同一个内联 SVG favicon
（`◎` 的雷达标记，用品牌色）。

### #11 「今日更新」的空态其实是对的，但当时没人确认过 🟢

这一条**没改**，只是记下来：`added` / `changed` 全空时页面写的是
「本次没有新增公告。如果你在等某个学校的通知，说明它还没发。」——
契约第 10 节要求的「明说本次没有新增或变化」，是满足的。**留作回归点。**

### #12 `review_status` 泄漏 —— 已经修好了（B 侧）🟢

`docs/DEMO-CHECKLIST.md` 第 8 节第 1 条记着「`GET/POST /api/posts` 的每条帖子都带 `review_status`，
论坛页的九字段自检会亮红框」。**这一轮走查时发现 B 已经修掉了**：
`POST /api/posts` 的 201 响应和 `GET /api/posts` 的 item 现在都恰好是契约那 9 个字段。
自检绿了，`DEMO-CHECKLIST.md` 已同步改掉。

> 顺带发现 C 自己那条自检的一个盲点：**列表 0 条时它查不出泄漏**（没东西可查）。
> 所以「自检绿」和「没有泄漏」不是一回事 —— 这一轮是靠**先发一条真帖再查**才验实的。
> 这条列进下面的「没改」里。

## 6. 数据新鲜度（「数据是什么时候的」）

> F 补。契约第 12 节第 4 小节（「stale 时前端该怎么措辞」）就是这一节的要求。
> `GET /api/freshness` 已经由 B 上线，A 产 `data/out/freshness.json`。

### 6.1 出现在哪三处（用户点名的三处）

| 位置 | 长什么样 | 文件 |
|---|---|---|
| **列表页 / 匹配页顶部** | 「196 条公告 · 数据更新于 27 分钟前 · 覆盖 37 所学校」+ 异常时追加警告 | `web/assets/common.js` 的 `freshnessBarHTML()`，宿主 `#freshness`（`notices.html` / `index.html`） |
| **某校的卡片上** | 该行 `meta` 里多一个徽章：「本次抓取失败（tls_handshake）」 | `schoolBadgeHTML()`，由 `notices.js` / `match.js` 的 `cardHTML()` 调用 |
| **今日更新页** | 新增一节「哪些没抓到 / 没解析出来」，逐校列出 + 每条的处置说明 | `freshnessIssuesHTML()`，宿主 `#fresh-wrap`（`daily.html`） |

### 6.2 三态各有各的话（**一个字都不许混**）

| `status` | 页面写法 | 为什么不能合并 |
|---|---|---|
| `failed` | 「**本次抓取失败**（tls_handshake）」+「这不是「它们没有更新」」 | 说成"没有更新" = 用户安心地以为自己了解情况，实际是我们坏了 |
| `empty` | 「**本次没解析出内容**（8/8 个栏目）」+「可能栏目改版，需人工确认」 | 说成"抓取失败"是冤枉；说成"没有更新"是掩盖。中间这一档必须存在 |
| `stale` | 「数据停留在 **10 月 16 日 08:20**（30 小时前）」 | 用"停留"不用"过期"：前者是事实，后者像在说数据坏了 |
| `unknown` | 「**还没有数据** —— 每日流程还没跑过」 | "没有数据"和"数据是新鲜的"是两个结论 |

三态的颜色也不同（失败=红、没解析/陈旧=黄、未知=灰），
而且**徽章带 `title`** —— 鼠标悬停/长按能看到完整解释。

### 6.3 三个实现决定（都是有理由的）

1. **接口优先、文件回退，但 4xx 不回退。** 接口 404/500 时读 `data/out/freshness.json`；
   接口明确 4xx 时**不显示** —— 文件兜底不会长出新事实。
2. **每页只取一次（`getFreshness()` 缓存 Promise）。**
   一页上三处要用它，各取各的会发三次请求，而且**三个结果可能不一样**（数据在跑的时候会变），
   同一个页面上两个数字互相打脸比不显示更坏。
3. **它单独一路超时（6 秒），不占主内容的 8 秒。** 第一版直接用 8 秒，
   实测「接口 500」态下新鲜度块要 13 秒才出现；而且慢到这个程度，
   **量具会以为"没渲染"** —— 我第一次就是这么误判的（见第 7 节）。
