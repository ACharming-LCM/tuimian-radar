```bash
# ① 起服务（B 的一键启动；它会把 web/ 同源挂载，所以没有跨域）

python run.py                     # 默认 http://127.0.0.1:8000

# ② 健康检查：数据有没有加载
curl http://127.0.0.1:8000/api/health
#   期望看到 loaded > 0、faculty_loaded > 0
#   （**别照死数字打勾**：这两个数会随抓取轮次变化，写死会在数据一变时误判成失败）

# ③ 浏览器打开（注意是根路径，不是 /web/）
http://127.0.0.1:8000/

# ④ 一条命令跑完下面的「演示 5 步」（B 加的自动冒烟，约 1.5 秒）
python server/tests/demo_rehearsal.py
#   它会自己起一个**临时端口**的服务实例、状态隔离在临时目录，
#   **不碰你在跑的 8000，也不碰 server/var/state.json**。
#   输出是「哪一步断了」，不是只给红绿。详见第 4 节。
```

- [ ] 服务起来了，`/api/health` 返回 200 且 `loaded > 0`
- [ ] 浏览器打开 `http://127.0.0.1:8000/` 能看到「匹配结果」页
- [ ] `python server/tests/demo_rehearsal.py` 输出 **5/5 步通过**

> **端口被占的应急**：如果 8000 起不来（本机当时被另一个副本占着），换成
> `python -m uvicorn server.app:app --port 8001`，后面所有 URL 把 8000 换成 8001。
> 本机彩排**全程用的是 8001**，所以这条路径是验过的。

## 4. 演示脚本 **7 步**（与 `RUN.md` 对齐，2026-10-17 统一）

> **这一段原来是 5 步，加了推送之后改成 7 步。**
> 顺序不是按"功能新旧"排的，是按**评委的注意力**排的：
> ①② 回答「我为什么要用这个」，③ 以后回答「它凭什么可信」。
> **先讲价值再讲可信**，评委才愿意听后半段。
>
> | 人演的 7 步（本节） | 对应冒烟脚本（`demo_rehearsal.py`，5 步） |
> |---|---|
> | ① 填画像 → ② 看推送 | （脚本不演交互，见 `demo_push.py` 的 6 步） |
> | ③ 今日更新 | ① 今日更新 |
> | （跳过公告列表这一步） | ② 公告列表 |
> | ④ 匹配 | ③ 背景匹配 |
> | ⑤ 详情 | — |
> | ⑥ 套磁信 | ④ 生成套磁信 |
> | — | ⑤ 论坛发帖 → 举报 → 审核 |
> | ⑦ 付费墙 | — |
>
> **两边的步数本来就不该一样**：脚本验"后端能不能供上货"，本节是"台上怎么讲"。
> 上面这张表是为了**上台的人能对上号**，不是要它们一一相等。

**① 填画像** → `/onboard.html`
- [ ] 四行：本科院校 / 专业 / 意向学校 / 意向方向
- [ ] 点「保存画像」→ 提示**「已保存并同步到服务端」**（这一句很重要：只存本地的话，推送读不到）
- [ ] 台词：*四行字决定你收到什么。填得越具体，推给你的越少、越准。*
- [ ] 如果提示的是「本地已保存，但**没同步到服务端**」→ **当场停**，服务端没通，后面 ② 会是空的

**② 看推送** → 点「看推送预览 →」（或 `/pushes.html`）
- [ ] 顶部**没有**「演示样例事件」横幅（有就是还在用样例，见 `docs/SCREENSHOTS.md`）
- [ ] 列表条数与页面上写的「共 N 条」一致；订阅身份是 20 条，免费身份是 3 条 + 付费墙
- [ ] **截止日三态同屏可见**：`截止 2026-XX-XX` / `该公告未公布截止日` / `⚠ 未能读取截止日，请点原文核对`+链接
- [ ] 台词：*这就是你会收到的推送。标题、学校、截止日，推送里就说完了。*
- [ ] 台词（**全场最重要的一句**）：*第三种「未能读取」不能省，也不能写成"暂无"——
      因为"我们不知道"和"它没有"是两件事，写成一样，人就不会去看原文了。*
- [ ] 数据变了会自己提示：等一会儿或手动触发抓取，顶部出现「后台刚更新了数据」
- [ ] 被问"这数据什么时候的"：指顶部那行「数据更新于 N 分钟前」，**它会自己走**

**③ 今日更新** → `/daily.html`
- [ ] 能看到「今天新增了什么 / 什么被改了 / 什么这轮没抓到 / 重新解析」

- [ ] 「过去 N 天的更新记录」有内容（这是"每天更新"的凭据）
- [ ] 台词：*新增是 0 的时候，是学校没发，不是我们坏了 —— 页面上写着。*
- [ ] 如果被问"你怎么证明每天在跑"：指「过去 N 天」那块 + `data/out/history/`

**④ 匹配结果：现场填一个真实背景** → `/` → 点右上「修改背景」
- [ ] 表单在主区的五个字段：**专业方向 / 成绩排名 / 英语 CET-6 / 科研经历 / 目标学位**

- [ ] 卡片上的截止日也是三态（读到了 / 确实没有 / 我们没读到），和 ② 同一套说法

**⑤ 点开第一条 → 看原文** → 点卡片标题进详情

**⑦ 付费墙** → `/pricing.html`

## 5. 降级路径（**服务起不来时，这条路必须能走通**）

答辩现场服务起不来是常事。这时**不用 API，用仓库里的样例数据**把演示走完。

```bash
# 只起一个静态服务器（没有后端）
cd <仓库根>
python -m http.server 5173
# 浏览器打开
http://127.0.0.1:5173/web/
```

- [ ] 页面能打开，**不是白屏**（我实测：匹配页、公告页、导师页、今日更新页、论坛页都正常渲染）
- [ ] 页脚写着「数据源：本地样例（接口没通，已回退）」—— **这是设计**，不是坏
- [ ] 显式指定样例模式也一样能用：`http://127.0.0.1:5173/web/?api=fixtures`
- [ ] 演示 5 步在样例数据下也能走完（内容会不一样：样例是固定的一份数据）

> **降级时不能做的两件事**（这两块只有真接口有）：
> 1. **今日更新页的「过去 N 天」不会显示**（那是接口数据，页面不会编）
> 2. **论坛现场发帖不能用**（发帖要写服务端状态）
> 现场如果只能走降级路径，就**跳过这两步**，别硬演。

## 8. 已知问题（彩排发现的，别在台上第一次遇到）

1. ~~**`review_status` 出现在前台响应里**（合规问题，B 侧修）~~

   论坛页自检是绿的。留档是因为它是「自检真的抓到过东西」的唯一证据。

2. **套磁信的引文还有碎片**（B 侧调挑句规则）
   用一条 PDF 表格类公告生成时，4 条引文里有：残缺标题（"…学术博士"）、
   表格数据行（"19 | 材料科学与工程学院 | 李某某 | …"）、

   **演示时挑一条正常的招生公告生成套磁信**，别用"答辩名单""送审名单"这类校内行政公告。

3. **服务端数据是内存缓存**（B 已修，但要知道）
   `server/live.py` 现在会按 mtime 重载。**如果演示前刚重跑过抓取管道，建议重启一次服务**再上台，
   免得"今日更新说有一批新的、公告列表却还是旧的"。

4. **默认排序还没用上 `relevance`**（B 侧）
   公告列表目前前排仍可能是南开「答辩评审名单」「论文送审双盲审名单」这类**校内行政信息**。
   A 已经把 `relevance` 字段给好了，等 B 接进排序。演示时**可以手动在列表页筛选**绕开。
