# 伙伴 2 任务书：给数据质量做一份**人工基准**

> **先读 `docs/PARTNER-SHARED.md`**，那里有快照规矩、边界和交付方式。

## 为什么这件事只有你能做，而且很重要

我这一晚所有的质量数字都是**机器自评**的：

- `deadline` 填充率 **31%（24/78）** —— 这是"填了多少"，**不是"填对了多少"**
- `majors` 填充率 81%，但我知道它有假阳性（"管理""教育"这类泛词会误命中）
- 78 条记录里，**只有约 51% 的标题明确与招考相关**

**我从来没测过准确率（precision）。** 如果 `deadline` 的准确率只有 60%，
那这个字段几乎是负资产——用户会拿一个错的日期去安排时间，
**比没有日期危险得多**（这句话我写进契约了，见 `contracts/api.md` 第 5 节）。

而且我试过用关键词规则去判断"这条公告跟招生有关吗"，**两个方向都错**：

```
误杀：南开「面向海外一流高校优秀本科毕业生招收直接攻读博士学位研究生简章」
误杀：电子科大「接收2027年优秀应届本科毕业生免试攻读研究生拟录取名单」
误收：北大 EMBA 招生简章
```

我用这个测量结果做了一个决定：**不做自动过滤**（理由见 `README.md`）。
所以现在唯一能推进的办法，就是**让一个人来标**。

## 你的三个任务（按优先级）

### 任务 1：标 78 条的相关性 ← 最要紧

文件：`data/out/label-template.tsv`（Excel 双击就能开，制表符分隔）

只填最后三列，**别动前面的列**：

| 列 | 填什么 |
|---|---|
| `admission_related` | `yes` / `no` / `unsure` |
| `deadline_correct` | 只对"有截止日"的那份填，见任务 2 |
| `note` | 拿不准的原因，一句话就够 |

**`unsure` 是有价值的答案，不是逃避。** 我需要的是你的真实判断。
如果你为了答案整齐而猜，这份基准就废了——而我会拿它去做决定。

判 `yes` 的标准：**这条公告是给"想报考/保研的学生"看的吗？**
（招生简章、专业目录、推免办法、夏令营通知、报名公告、考核细则、拟录取名单 →
`yes`；新生报到、注册、选课、答辩名单、党建、导师评优、墙报展 → `no`）

### 任务 2：抽查 24 条截止日的准确率 ← 第二要紧

文件：`data/out/label-deadline-sample.tsv`

机器给每条抽了一个 `machine_deadline`。你要做的是**点开原文**
（表里有 `url` 列），判断这个日期**是不是公告里真正的截止日**，填在 `correct_date_or_blank`：

- 对 → 填 `ok`
- 错 → 填**正确的日期**（YYYY-MM-DD），或者填 `无截止日`（如果公告里根本没有）
- 拿不准 → 填 `unsure`

**这个数字我一次都没测过。** 它会直接决定我们要不要在界面上把 `deadline` 标成"疑似"，
或者干脆不显示。所以**请慢一点、准一点**，不要图快。

### 任务 3：独立抽查 10 条记录的字段对不对

从 78 条里**随机挑 10 条**（不要挑看起来整齐的），
点开原文，核对这三个字段：

- `deadline`（如果有）
- `majors`（公告涉及哪些专业）
- `apply_mode`（推免 / 夏令营 / 统考 / …）

把你发现的**每一个错**都记下来，包括"应该是什么"。写成一个 md 交回来。

> 为什么要随机：**只挑整齐的样本会得到虚高的精度。** 我在这个项目里已经犯过一次——
> 我早期估"栏目发现精度约 60%"，后来用完整基准一测，**真实值是 31%**。
> 偏差的来源就是我那 8 个样本是我自己挑的。
