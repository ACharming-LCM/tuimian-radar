## 0. 怎么量（可复现，别信"我看了一眼")

```powershell

cd C:\Users\<user>\OneDrive\文档\deepseek-harness\default-workspace
$env:CDP_PORT='9333'                     # 先起好 headless Chrome（脚本头部有命令）

# ① 9 页 × 375×812，逐页截图 + 量
$n  = Invoke-RestMethod 'http://127.0.0.1:8001/api/notices?size=50'
$id = ($n.items | Where-Object { $_.deadline } | Select-Object -First 1).id
& 'D:\nodejs\node.exe' _c-tasks.js m375 http://127.0.0.1:8001 _c-tasks-m375.json $id u_quota_c1 u_shot_m1
& 'D:\nodejs\node.exe' _c-cdp.js _c-tasks-m375.json _c-f-m2
& 'D:\nodejs\node.exe' _c-table.js _c-f-m2          # 一行一页，人读

# ② 手机核心路径（会真的点「复制邮箱」、真的把剪贴板读回来）
& 'D:\nodejs\node.exe' _c-corepath.js $id u_core_1
& 'D:\nodejs\node.exe' _c-cdp.js _c-tasks-corepath.json _c-f-mcore
```

`_c-cdp.js` 每页除了截图，还量回来这些（写进 `report.json`）：

| 字段 | 是什么 | 这一页靠它证明什么 |
|---|---|---|
| `hOverflow` | `scrollWidth - clientWidth` | 横向滚动 = 0 |
| `tap.small / tap.total` | 触控目标 < 44px 的个数 / 总数 | 手指点得准 |
| `fs` | 关键元素的 `font-size` | 该看清的字够大 |
| `clip` | 点 `[data-copy]` 后**读回剪贴板**并与 `data-copy` 比对 | 复制邮箱真的能用 |
| `mailto` | `a[href^="mailto:"]` 存在且地址非空 | 点一下就能写信 |
| `badWords` | 页面上出现 `undefined` / `NaN` / `[object Object]` | 没有漏渲染 |

**两个坑**（C 记的，我复核过，都真的）：

1. **必须 `Network.setCacheDisabled`**（脚本里已加）。同一浏览器会话反复导航，
   Chrome 会把 `style.css` 从内存缓存拿出来 —— 于是"改好了"和"量到的是旧的"混在一起。
2. **量之前先重新取公告 id**。数据在跑的时候会变，上一分钟的 id 这一分钟可能 404，
   于是详情页那一行测的是"404 态"，不是"详情态"。

## 1. 结论（先看这一节）

| 硬指标（用户给的） | 结果 | 依据 |
|---|---|---|
| 横向滚动 = 0 | **9 页全 0** | `hOverflow` 全为 0 |
| 可点区域 ≥ 44px | **0 / 399 个不达标** | `tap.small = 0`（9 页累计 399 个可点元素） |
| 正文 ≥ 15px | **15px**（列表标题 16.5 / 详情正文 15.5 / 子标签 13~14.5） | `fontBody` / `fs` |
| 核心路径能走完 | **5 步全通**，两处「复制邮箱」**剪贴板读回来逐字一致** | `clip.matched = true` × 2 |
| 重要信息不缩放能读 | 公告标题 16.5px / 截止日 chip 13.5px / 导师方向 15px | `fs` |

**改之前不达标的有三处**，都在第 2 节；**这一轮我改了两处**（导航换行、截止日字号），
另一处（横向溢出）是 C 改的，我复核了根因和修法。

> **说清楚一个口径**：上面「0 / 399」里的 399 是**可点元素总数**，不是"9 页各 399 个"。
> 分页数在第 3 节的表里，最小的详情页 12 个，最大的导师页 164 个。

## 2. 发现的问题：改了的

### #1 导航在 375 宽下换行，每页首屏白占 48px 🔴 我这一轮改的

6 个链接 12px 横向内边距时总宽 **368px**，而这一行只有 **347px** ——
于是「订阅」被挤到第二行，导航条从 46px 变成 **95px 高**。
这不是"看着有点挤"，是**每一页**的首屏都少了一行内容，而且手机上第一屏最贵。

改法：`.nav a { padding: 12px 8px }` + `.nav { gap: 0 }`。
总宽 ≈ 344px，一行放得下；**触控高度仍是 46px**（≥44，没有为了放下而把手指解放区压小）。

验证：`navH` 95 → **46**，6 个链接 `top` 全部相同（同一行），`tap.small` 仍为 0。

### #2 「截止日」是全页最小的字，而且比装饰性标签还小 🟠 我这一轮改的

`.deadline` 是 **12px**（我实测的 computed 值），而 `.chip` 有 13.5px ——
**一页里最贵的两个数字（哪天截止、还剩几天）比标签还小**。
C 的交接文档说"已从 12.5px 提到 13.5px"，**实测没有生效**（可能改的是别的选择器）。
这一条正是"文档说改了、屏幕没改"的例子，所以我按量出来的值改。

改法：`.deadline { font-size: 13.5px; padding: 3px 8px }`，`.dl-label` 13px。

### #3 「只看带附件」的勾选框 20×20 🟡 我这一轮改了尺寸

`label` 本身有 44px（所以**点得着**，测量脚本也把这种假阳性排除了），
但**看得见**是另一件事：20×20 在手机上像是没做完。提到 **22×22**。
（说明：`.check input` 的 `min-height: 44px` 不会作用于 checkbox 本身，
所以这里分两件事处理 —— 触控面积交给 label，视觉尺寸交给 input。）

### #4 详情页整页要左右滑（**C 改的，我复核过根因**）🟢

改之前详情页 `scrollWidth = 691px > 375px`，整页要左右滑。
根因不是容器宽度写错，而是正文里有一段 **321 字、没有空格的连续文本**（从 PDF 抽出来的），
浏览器在那一段不做换行。

修法（C 做的，我复核）：`.dbody, .ncard .title, .cite-quote, .letter-body …`
统一 `overflow-wrap: anywhere` + `word-break: break-word`，再加 `html, body { overflow-x: hidden }`。
**这是对的**：任何外部文本都可能出现长串，不能指望上游把空格补好。

### #5 套磁信页没有收件人 🟠 我这一轮**加了指引**，架构没动

这是交接文档列的最重要的一件。**问题本身是真的**：
核心路径是"生成信 → 复制邮箱"，但信是按**公告**生成的，公告里没有老师邮箱，
于是学生到这一页会停住 —— 信写好了，不知道发给谁。

我做的：在第 3 节加一块「收件人」，明确写**这封信还没有收件人**、为什么、下一步去哪，
并给一个 44px 的按钮「去导师页挑人、复制邮箱 →」。

我**没做**的（这是产品决定，得你拍）：要不要改信息架构，比如
「从导师页选人 → 带着邮箱进套磁信页」。两种做法都合理，但走法完全不同，
不该我一个人定，见第 4 节第 1 条。

### 3.1 核心路径（手机上真的走了一遍）

| 步骤 | 结果 |
|---|---|
| 列表 → 一眼看到截止日 | ✅ 卡片上 `截止 2026-10-24` + `还剩 7 天`，13.5px |
| → 详情 | ✅ 正文、附件、「看原文」都在；整页不横滑 |
| → 生成套磁信 | ✅ 引文 3~5 条，每条能点回公告原文 |
| → 导师页：邮箱 + mailto | ✅ `mailto:teacher26@pku.edu.cn`（`128×44`），地址非空 |
| → **复制邮箱**（导师页） | ✅ 点完按钮变「已复制 ✓」，**剪贴板读回来 = `teacher26@pku.edu.cn`**，与 `data-copy` 一致 |

**注意**：演示如果用局域网 IP（`http://192.168.x.x:8001`）打开，`navigator.clipboard` 直接是 undefined，
会走 `execCommand` 兜底 —— 那条路也测过能成功，但**演示优先用 `127.0.0.1`**。

## 4. 发现的问题：没改的，以及为什么

### 1. 套磁信页「先选导师还是先写信」的信息架构 ⏸️ 需要人拍

现在的路径是：公告 → 生成信 → （停住）→ 去导师页挑人 → 复制邮箱 → 回来发。
**能走通，但绕了一下**。

另一种做法：导师页 → 选一位老师 → 「给这位老师写信」（把 email 带进信页）。
两种都合理，区别在**产品定位**：

- 「信息聚合工具」→ 现在这套够了（信是附属品）；
- 「保研决策助手」→ 应该从"人"出发，先挑导师再写信。

**这正是负责人一直悬着没拍的那件事（`docs/PPT-OUTLINE.md` 的定位问题）**，
定了它，这一页的信息架构自然就定了。我不替产品拍，但我把代价写清楚了：
不定的话，演示时走到套磁信这一步，评委很容易问"这封信发给谁"，而页面只能让你"自己去找"。

**我这一轮做到的**：至少让它不再是一个死胡同 —— 页面自己说清"还没有收件人"并给出入口。

### 2. 正文是 inline 链接的地方，做不到 44px 🟢 有豁免

一句话中间的"点这里"不可能做成 44px 的按钮（做了就把句子拆碎了）。
WCAG 2.5.5 对 **inline link 本来就有豁免**，这不是我们偷懒。
**但**我把这一页里"唯一必要的那一步"改成了真按钮（第 2 节 #5），
因为那个位置原本是一个 38×16 的 inline 链接 —— 它**不是**句子中间的补充信息，
而是这一页缺的那一步。分清楚这两者，才叫"按标准做"而不是"拿标准当挡箭牌"。

### 3. 论坛的院系/标签下拉贴边，看着有点挤 🟡 没改

原因是那一排是横向滚动的 chip 组，最左边那个贴住容器边。
把内边距调大能缓解，但会挤掉右边可见的 chip 数量 —— **换来的是"好看一点"，
代价是"一眼能看到的筛选项少一个"**。手机上我选后者。等有真人试用反馈再动。

### 4. PDF 表格类正文在块内横滑 🟡 故意的

`.body-pre` 用 `overflow-x: auto`，**页面本身不滑**，只有那一块能滑。
这是取舍：表格靠换行/空格对齐，重排只会更乱（这一条 `FRONTEND-STATE.md` 里也有）。
手机上勉强能读，字号收到 12px 让多数行放得下。真要好读，得在上游把表格转成真正的表格结构 —— 那是数据侧的事。

### 5. 今日更新的「过去 N 天」只有 1 天 🟢 不是前端能补

A 的 `data/out/history/` 现在只有 1 个快照日，前端不编数字。等抓取多跑几天自然就有。

## 5. 这次一起做掉的两件（原本不在手机这一环里）

1. **数据新鲜度**（交接文档 §6.3，用户点名的三处）：列表页 / 匹配页顶部一行
   「196 条公告 · 数据更新于 27 分钟前 · 覆盖 37 所学校」；某校抓取失败时**在它的卡片上标出来**；
   今日更新页新增「哪些没抓到 / 没解析出来」一节。
   三种状态（`failed` / `empty` / `stale`）各有各的措辞和颜色 —— **"没抓到"不许说得像"没有变化"**。
   详见 `docs/FRONTEND-STATE.md` 第 6 节。

2. **页脚数据源在三态下都如实标**（C 改的，我复核）：失败时不再宣称"本地样例"。

## 7. 一句话

**手机这一环的硬指标是"能用"，不是"好看"。**
横向不滑、手指点得准、该看清的字够大、复制邮箱真的能用 —— 这四件事决定它在食堂里能不能被用起来。
剩下的（导航挤不挤、下拉贴不贴边）都得等真人坐在旁边用五分钟才知道该改哪儿，
那是 `docs/USER-TEST.md` 的事，不是我在这一页能编出来的。
