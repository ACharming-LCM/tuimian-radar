> **这份文档从零讲起，不假设读者知道任何事。**
> 给三种人看：① 第一次接触这个项目的决策者/评委；② 刚接手某个模块的 agent；
> ③ 三天后回来看「我们当初为什么这么定」的团队成员。
>
> 最后更新：2026-10-17 19:30。**所有数字都是实测**（来源见每节标注），
> 不是估算，也不是设计目标。

## 一、一句话

**把散在各高校研究生院/院系官网的招生公告抓下来，结构化，按你的背景匹配，
并且在"今天有什么值得你注意的"这件事上主动通知你。**

它叫「推免雷达」。推免 = 推荐免试研究生（保研）。

---

## 二、给谁用，用在什么场景

**用户画像**：大三下 / 大四上的本科生，正在准备保研（推免）。

**他真实的一天是这样的**：

1. 打开 20 多个学校的研究生院网站，一个个翻"招生公告"栏目，看有没有新的。
2. 点开一条公告，正文里没有截止日 —— **截止日期在附件 PDF 里**。下载、打开、找。
3. 发现截止日是下周，但报名材料要求里有三项他没准备。
4. 想去联系导师，但不知道哪个老师做他这个方向 —— 到院系师资页一个个翻，
   教授、研究员、副研究员混在一起，方向写得含糊。
5. 第二天重复第 1 步。

**核心痛点不是"找不到信息"，是"不知道今天有没有该我动作的事"。**
漏掉一条 = 错过一次报名 = 这一年的保研少一个选择。

**现有替代方案为什么不够**：

| 现状 | 缺什么 |
|---|---|
| 收藏一堆官网，每天手动刷 | 会漏；而且"没变化"和"我没刷"分不清 |
| 微信群/学长传消息 | 不可靠、不可查、只覆盖少数学校 |
| 已有的保研 App/公众号 | 二手信息，看不到原文；而且**无法核对它说得对不对** |

## 三、我们的产品主张（这一段是整份文档最要紧的）

> **不是"又一个信息聚合"，是"一个说得清自己哪里不知道的工具"。**

信息聚合这个事，谁都能做。我们赌的是另一件事：

**保研决策的代价太高，所以"可信"比"多"值钱。**

一个说"我抓到了 286 条"的工具，用户没法验证；
一个说"这 286 条里有 89 条我们读到了截止日、153 条公告里确实没写、
44 条我们没读到请你自己去看原文"的工具，**用户能验证，也能据此行动**。

这个主张落在三个具体机制上：

### 1. 三态字段：`found` / `absent` / `unknown`

同一个"没有截止日"，可能是两件完全不同的事：

- **`absent`**：公告正文我们读到了，里面**确实没写**截止日 → 用户该放心
- **`unknown`**：我们**没读到**（正文没抓全 / 在图片里 / 在附件里） → 用户该去点原文

**这两件事如果显示成同一句话，用户会照着错的结论做决定**
（"这条不用赶" vs "这条我不知道什么时候截止"）。

实测：286 条里 `found` 89 / `absent` 153 / `unknown` 44。
**注意 `absent` 是 153 条** —— 如果把它们都算成"没抽到"，抽不到率就是 68.9%；
分开之后，真实的"没读到"是 44 条（15%）。**同一个数据，两种说法，差 4 倍。**

### 2. 逐条回链原文

套磁信里每一句引文、每一条推送，都带原始链接。**这不是功能，是防编造机制**：

- 信是模板生成的，但引用的每一句都逐字来自公告原文，点一下就能回官网核对
- 推送里每条都带 `url`，**免费用户也带**

### 3. "没有"和"我们不知道"必须说成两句话

这条贯穿全项目，出现在至少六个地方：

| 场景 | 错误说法 | 我们的说法 |
|---|---|---|
| 推送为空 | "今天没有新公告" | 分六种：没填画像 / 事件文件还没写 / **数据太旧我们不知道** / 没匹配上 / 全是补抓的旧公告 / 有内容 |
| 字段缺失 | "没有截止日" | `absent`（确实没有）vs `unknown`（没读到） |
| 抓取状态 | "没变化" | `failed`（抓失败了）/ `empty`（抓到了但 0 条）/ `stale`（太久没抓）/ `ok` |
| 变更类型 | "学校更新了" | `added`（学校新发）/ `changed`（学校改了内容）/ **`reparsed`（我们改了代码，公告一个字没动）** |
| 补抓的旧公告 | "【新公告】2013 年…" | 排除，并说「这是补抓的历史公告，不计入推送」 |

## 四、谁在做，怎么协作

**三个人，各自指挥一个 AI agent，同一个 git 仓库并行干。**
（"三天"指的是集中开发期，实际是几个高强度的工作日。）

| 人 | 目录 | 负责 |
|---|---|---|
| **A** | `collector/` + `data/out/` | 抓取、解析、字段抽取、数据质量门禁、事件流 |
| **B** | `server/` + `contracts/` | HTTP 接口、契约、匹配/套磁信/付费/论坛/推送的业务逻辑 |
| **C/F** | `web/` + `docs/` | 页面、演示、截图、手机端 |
| **统筹者** | `status/` + `journal/` + `issues/` | **不写代码**：读上报、判谁卡谁、派单、验收（见 `docs/ORCHESTRATOR.md`） |

**为什么这么组织**（这是踩过坑之后的决定）：

1. **目录所有制是硬的**：只能写自己名下的目录，要改别人的东西就提 `issues/`。
   实测原因很简单：**两个 AI 同时写同一个文件，项目就乱**。
2. **契约是唯一的接口**：`contracts/api.md`（HTTP 形状）+ `notice.schema.json`（数据结构）。
   **先改契约，再改代码**，每次改动记 `CHANGELOG.md`。
3. **AI 之间靠文件沟通，不开会**：`journal/` 是日报（追加），`status/` 是当前状态（覆盖），
   `issues/` 是待裁决。
4. **不用 agent 做验核**：实测过一次 83 个 agent 跑核验，45 个因余额不足失败，
   而失败的被裁决逻辑静默算成"这条不成立" —— **失败被伪装成结论**，比浪费钱危险得多。

## 五、时间线与交付

- **交付日：10-20**。
- **交什么**：一份 PDF（方案说明）+ **一个能当场演示的成果**（2–3 分钟视频 / 现场演示）。
- **评委性质：商业向**。所以"技术多牛"不是重点，**"谁会用、为什么用、怎么持续"才是**。
- **判据（用户原话）**：**"能被录进 2-3 分钟视频"比"功能多"重要。**

这个判据决定了很多取舍，比如：

- 推送链做扎实（能录视频），而不是多加三个接口
- 演示脚本要能一条命令跑通（`demo_push.py` 6 步、`demo_rehearsal.py` 5 步）
- 砍功能的标准：**没通就砍，但砍的同时要改 PDF 措辞、确认演示还能跑**

## 六、现在的真实状态（2026-10-17 实测）

### 数据（A 的产出，`data/out/`）

公告          286 条
学校          17 所
抓取单元      37 个（20 个有产出，17 个 0 条 —— 见下）
正文非空      286/286 = 100%
截止日        89 条读到（31%）、153 条公告里没写、44 条没读到
附件          66 条有
导师          557 人 / 6 个院系（有研究方向的 379 人 = 68%）
事件流        286 条（append-only，其中 221 条是补抓的历史公告）

**必须如实说的两句**：

1. **17 个抓取单元产出 0 条**。原因分诊过：JS/SPA 渲染、登录后可见、或者栏目本身
   就没有招生信息。**按用户指示不新增站点** —— 20 个站的稳定性比多 5 个站值钱。
2. **导师层是"手工配置能力"，不是"泛化能力"**。已跑通 6 个院系

   **换一所学校不能自动跑**。对外只能说"已跑通 6 个院系"，不能说"支持多校导师"。

## 七、已经拍了的决定（别再重新论证）

| 决定 | 理由 | 谁拍的 |
|---|---|---|
| **不新增抓取站点** | 边际收益已降；17 个 0 条站点要预渲染，工程量大于收益 | 用户 |
| **不接 LLM** | 模型选型和 key 归属未定；模板版 + 逐条回链已能演示机制 | 团队未拍 = 不做 |
| **支付是模拟的** | 学生团队拿不到微信支付商户号；响应里 `method` 和 `_note` 都如实标了 | 现实约束 |
| **不隐藏任何结果** | `relevance` 只排序、不隐藏；已截止的公告沉底但不压掉 | A + B |
| **宁可少、不可假** | 宁可 `null` + 警告，不编一个日期；宁可少一条真导师，不编一条假导师 | A（写进交接文档） |
| **主动交代边界** | PPT 里有专门一页"我们哪里不行"——**一个知道自己边界的团队更可信** | C（PPT 大纲） |
| **"实时"不许说** | 抓一轮 **28~34 分钟**（取决于缓存命中率）。能说的是"**准实时：5 分钟内发现，30 秒内可见**" | B |

## 八、还没拍的（只有决策者能定）

这四件一直悬着，谁也替不了：

| # | 事 | 为什么要决策者 | 不拍的后果 |
|---|---|---|---|
| 1 | **找 3 个真保研生试用** | 技术都通了，但"真有人要吗"没有证据；人得他去约 | PDF 里只能写"待验证" |
| 2 | **PPT 定位**：「信息聚合工具」还是「保研决策助手」 | 后面每一页的措辞都取决于这一句 | 页面和台词会左右摇摆 |
| 3 | **挂 Windows 计划任务**（真·日更） | 要改系统设置 | "每天更新"只有单次证据，没有连续性 |
| 4 | **抓取频率要不要提到 5 分钟** | A 要改增量抓取；会持续请求别人学校的服务器 | 演示时"实时"那一档拿不出来 |

**另外两件产品判断**（B 已给出建议，等一句话）：

- **论坛的 `reply_count` 是假字段**（恒为 0，前端还显示"回复 0"）：补回复接口还是拿掉？
- **推送首条要不要优先"有明确截止日"的**（现在首条可能是"未公布截止日"）：
  这是再一级分组，等于把 `relevance` 降为第二级。

## 九、术语表（外人看不懂的词）

| 词 | 意思 |
|---|---|
| **推免** | 推荐免试研究生，即"保研" |
| **三态** | `found`（读到了）/ `absent`（确实没有）/ `unknown`（没读到） |
| **`relevance`** | 公告跟"招生"的相关程度，0/1/2 三档。**只用于排序，绝不用来隐藏结果** |
| **`reparsed`** | 我们改了抽取代码，公告**一个字没动**。绝不能算成"学校更新了" |
| **`is_backfill`** | 这条事件是"我们补抓时翻出来的旧公告"，不是"学校今天新发的" |
| **`field_state`** | 每个字段的可信度三态，数据层落盘给接口层用 |
| **fixture** | 接口响应的**形状基准**。形状永久有效，数值只对 `_as_of` 那天有效 |
| **门禁** | 自动化的契约检查（152 条）。**默认形状必须等于 fixture，一个多余键都不加** |
| **冒烟** | 按演示顺序打真实接口的脚本，验"上台那天会不会断" |
| **事件流** | `events.jsonl`，append-only，回答"历史上发生过哪些值得打扰用户的事" |
| **抓取单元** | 一个 `(school, unit)`，如"浙江大学 / 研究生院" |

## 十、如果被问到，这样答（FAQ）

**Q：你们抓了多少学校？**
> **已跑通 17 所高校、20 个抓取单元**，286 条公告。另外尝试了 37 个单元，
> 17 个抓不到（JS 渲染 / 登录后可见），我们**没算进覆盖里**。

**Q：截止日怎么只有 31%？**
> 31% 是"读到了"的比例。剩下 69% 里，**153 条是公告里真的没写**（宣传册、拟录取名单、
> 讲座公告这类本来就没有），44 条是我们没读到（在图片或附件里）。
> **我们不会把这两件事说成同一件** —— 后者会让用户去点原文，前者不会。

**Q：数据多久更新一次？**
> **抓取是分钟级的，不是秒级** —— 源头是各校官网，我们不可能比学校发得更快。
> 一轮 28~34 分钟（取决于缓存命中率）。但**数据一落地，页面 30 秒内就能看到**（前端轮询 + 后端按文件修改时间重载）。
> 而且数据旧了界面会自己说："数据是 1.7 天前，我们不知道今天有没有新的"。

**Q：套磁信是 AI 写的吗？**
> **现在是模板生成的，不是大模型**（响应里 `method: "template"` 明说了）。
> 但**机制已经建好了**：每一句引文都逐字来自公告原文、可点回核对。
> 接模型只是替换正文，回链机制不变 —— 那才是防编造的关键。

**Q：付费墙是不是把公开信息藏起来？**
> 不是。免费版能看到全部公告列表、每天 3 条详情、**每条推送都带原文链接**。
> 订阅买的是**持续服务**：截止日提醒（T-7/T-3/T-1）、套磁信、推送的完整列表。
> **推送故意给免费用户前 3 条** —— 只有付费才能看到的推送，用户在购买前没法判断值不值。

**Q：论坛有人骂某个实验室怎么办？**
> 有完整闭环：**收得到**（举报 + 去重 + 限速）、**处理得掉**（队列带 24 小时时限）、
> **留得下痕**（append-only 审计，每条自带原文快照）、**说得出依据**（固定类别 + 完整链条）。
> 作者能申诉，举报人只看到"已处理"、看不到别人是否举报过。

**Q：你们哪里做得不好？**（**主动讲，别等他问**）
> 三个：① 17 个抓取单元抓不到；② 导师层只跑通 6 个院系，不是各校通用；
> ③ 没接真实支付（拿不到商户号）、没接大模型（选型未定）。
> **这三条都在 PPT 里单独一页写着**。
