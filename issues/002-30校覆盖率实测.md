# 002 30 所学校的覆盖率实测谁做、什么时候出数

- **提出**：A  2026-10-16 21:20
- **状态**：open
- **阻塞谁**：D2 的全部排期
- **背景**：

  README 里写了"加学校 = 加一行配置，栏目自动发现"。但这个承诺**没有被验证过**。

  实测浙大 3 个站点：物理学院 ✅ 自动发现了正确栏目；材料学院 ✅；
  **校级研究生招生网 ❌** —— 自动发现到的是"在职攻读硕士学位"栏目，抓回来 2018 年的陈年公告。
  真实推免主栏目是 `c28498`，必须人工指定。

  所以真实覆盖率可能是 100%，也可能是 60%。**这两个数字对应的 D2 工作量差一倍。**
  如果是 60%，就必须配一份人工指定栏目的兜底清单，"加一行"这个卖点要改口径。

- **选项**：
  1. 一个人明天上午专门干这件事：填 30 所学校首页 → 跑 `--details 0` → 人工核对每个发现的栏目对不对 → 出覆盖率数字
  2. 三个人各分 10 所，中午汇总
- **需要**：**建议选 1**，这件事有判断成分（"这个栏目对不对"要人看），三个人分着做反而慢。谁时间最松谁做。
- **结论**：**已完成，21:22。数字比预想的差，但失败原因比预想的好。**

## 结论（2026-10-16 21:22 实测）

工具：`collector/tools/add_sites.py`，报告：`data/out/coverage.md`。

| 环节 | 数字 |
|---|---|
| 候选站点 | 50（40 个校级研招/研究生院 + 10 个院系） |
| 公网可达 | **37（74%）** |
| 自动发现到招生类栏目 | **16（32%）**；放宽 URL 规则前只有 12 |
| 抽查 8 个，栏目判定正确 | 5 个 → 精度约 60% → **真正可用约 10 所** |

### 两个必须记住的判断

1. **"不可达"里 23/26 只是域名猜错，不是抓不到。** 已按原因分类（DNS 不存在 / WAF / 超时）。
   所以"50 所里只能抓 37 所"是**低估**——真实可达率更高，缺的只是正确域名。
   真正抓不到的只有：中山大学（HTTP 403 WAF）、重庆大学（HTTP 412 WAF）、
   深圳大学（超时）、以及内网 IP 的站点（见 issues/001）。

2. **自动发现是"辅助"不是"自动"。** 抽查 8 个里错了 3 个：
   - 浙大研究生招生网 → 发现了「在职攻读硕士学位」这种错栏目（真栏目是 `c28498`）
   - 清华研究生招生网 → 只发现了「国际招生」（留学生），真资讯在 `yzbm` 子域
   - 华东师大研究生院 → 发现的是「学位申请系统」，不是公告列表

   对的 5 个：复旦（`夏令营/推免` 栏目，score 17）、北大（`硕士招生公示`/`博士招生公示`）、
   重庆大学（`2027年硕士研究生招生章程及专业目录`）、浙大物理、浙大材料。

3. **四类硬限制**（决定了产品的真实覆盖面）：
   - 首页只是门户，资讯在子域 → 人工指定栏目即可修（清华）
   - 公告发在微信公众号 → 无开放接口，**比赛期间放弃**（北大首页大量链接指向 `mp.weixin.qq.com`）
   - SPA 异步加载 → 需浏览器渲染，4 天做不完（武大 `gs.whu.edu.cn`）
   - WAF 反爬 → 绕行有合规风险，不建议（中山、重大）

### 对 D2/D3 排期的影响

**策略从"覆盖 30 所"改成"锁定 10 所，把召回率做满"。**
理由：漏一条报名通知的代价，远大于少覆盖 20 所学校。
剩下的人工工作 = 为这 10 所人工核对/指定栏目，一次性成本，之后稳定。

- **状态**：closed


## 具体怎么测

```bash
cd collector
# 1) 把 30 所学校首页填进 sites.json 的 schools 数组（只填 school/unit/homepage）
# 2) 跑列表发现，不抓详情，秒级
python crawl.py --details 0
# 3) 看输出里每个站点的 "-> [分数] 栏目名  url"，人工判断是不是推免相关栏目
# 4) 统计：正确发现数 / 30 = 覆盖率
```
