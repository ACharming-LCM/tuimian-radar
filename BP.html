推免雷达 · BP（2026-10-20 版）

一句话：把 29 所高校官网的推免公告变成「今天该你办的 3 件事」，每条都能点回原文。 不是保研指导平台，不预测录取概率；它解决的是「漏看一条公告，就少一次机会」。

2. 问题

2.1 用户每天面对什么

准备推免的学生要同时盯：

  • 20+ 所学校的研究生院、院系官网；
  • 夏令营、预推免、推免服务系统三个时间窗口；
  • 截止日常常不在正文里，而在附件 PDF、表格或图片里；
  • 导师方向、邮箱散落在各院系师资页。

真正的问题不是「信息少」，而是「不知道今天有没有该我动作的事」。 错过一条报名通知，代价是一整年的机会。

2.2 现有方案为什么不够

方案 问题
手动刷官网 29 所学校 × 多个栏目，必然漏；公告还会被静默修改、补附件
微信群 / QQ 群 二手信息，转发滞后，无法核对原文，广告多
现有保研 App / 公众号 多为经验帖与广告；公告常是二手转载，点不回原文，也无法说清哪条没抓到
学校自己 不跨校聚合，不按个人背景排序

3. 产品

3.1 一条完整链路

  1. 填画像：本科院校、专业、意向学校、方向（四行字）。
  2. 拿推送：每天 10 条以内，每条写明「为什么推给你」「还剩几天」。
  3. 点开核对：材料清单、联系方式、附件、正文、原文链接，一条不缺。
  4. 匹配导师：按研究方向匹配，给出邮箱与主页。
  5. 生成套磁信：模板生成，4 条引文逐条可回链原文（明确标注未接模型）。
  6. 关注学院：有新公告时站内提醒。

3.2 三个不能让步的设计

① 字段三态，绝不把「不知道」说成「没有」

状态 含义 页面措辞
found 读到了 直接显示日期
absent 正文可信，学校确实没写 「该公告未公布截止日」
unknown 我们没读到（扫描件/正文太短/兜底抓取） 「未能读取，请点原文核对」

当前数据：found 749 / absent 1199 / unknown 698。 截止日明确且未过的只有 40 条——这个数很小，但不是 bug：多数学校本来就不写截止日，我们不猜。

一个真实案例（可现场演示）：北京大学《2027 年接收推荐免试研究生办法（校本部）》 正文里没有写截止日，截止日实际在附件 PDF 里。如果系统把它标成「无截止日」， 学生会以为随时能报；我们的做法是标成 absent（学校没写），同时保留附件与原文链接， 页面上写「该公告未公布截止日」。

一句话：我们不保证知道答案，但保证不把「不知道」说成「没有」。

② 每条都能回原文

推送、导师、套磁信引文都带原始 URL。用户不需要相信我们，只需要点一下。

③ 空了就说空

没有对口的招生公告时，显示「今天没有」，而不是拿讲座、会议、报考点公告凑满一屏。

3.3 首页长什么样

  • 顶部：数据更新于几小时前、7 天内截止 18 条、已截止/未知各多少条。
  • 中部：推送卡片，标明「招生通知 / 其他 / 参考资料」。
  • 右侧：按研究方向匹配的导师。
  • 底部：每条都能「看原文 / 详情页」。

4. 技术与数据

4.1 数据管道

首页 → 自动发现招生栏目 → 列表翻页 → 详情正文/附件
     → 字段抽取（截止日/专业/材料/联系方式）
     → 内容分类（招生通知/目录/EMBA/其他）
     → 去重（内容指纹 + 同标题）→ 事件流 → 推送打分
  • 抓取遵守 1–2 秒/请求的礼貌间隔，走本地缓存，不绕验证码。
  • 数据写入 .tmp 后原子替换；条数骤降 20% 拒绝落盘（事故后加的门禁）。
  • 支持增量（约 2 分钟）与全量（16–60 分钟）两种模式。

4.2 推送打分

  • 四个正向维度：意向学校 0.35、专业 0.25、方向 0.20、新鲜度 0.20。
  • 紧急度乘数：7 天内截止 ×2.0，8–14 天 ×1.5，15–30 天 ×1.2。
  • 负向维度：EMBA/在职、报考点/考场类事务公告降权（不是隐藏）。
  • 硬门槛：非招生类（讲座/会议/名单）不进首屏；目录/简章进「参考资料」区。
  • 每条都输出 why（人话）和 score_dims（四维），不暴露内部加权和。

4.3 质量保障

  • 233 条自动门禁：契约形状、三态不变量、数据健康、接口行为、公网只读、请求体上限。
  • 数据健康门禁：正文空壳、分类自洽、悬空事件、发布日缺失率、截止日 unknown 占比突变、标题坍塌。
  • 三校外部对照：漏率从 74.1% 降到 17.4%（北大 155/212、川大 266/302、清华物理 19/19）。
  • 其余 26 所尚未做外部对照——这是已知边界，写在 README 里。

5. 市场

  • 目标人群：每年推免生约 15–20 万人（按推免资格高校与名额估算，待核实）；加上考研统考人群可扩展到 300 万+，但本产品第一阶段只服务推免。
  • 付费意愿：一次错过报名的机会成本远高于 ¥29/月。当前定价参照同类信息服务的低价位，属于「无脑买」区间。
  • 切入顺序：先做推免季最焦虑的 10 所目标校（用户集中、公告量适中），再横向扩校。
  • 扩展路径：推免 → 夏令营/预推免 → 考研调剂 → 海外申请；数据能力可复用到任何「官网公告 + 时间窗口」场景。

壁垒不是模型，是数据管道 + 可信度。 抓取、分类、去重、三态、门禁这些「不性感」的工程，正是竞品最难补的部分。

7. 商业模式

  1. C 端订阅：免费每天看前 10 条推送；订阅 ¥29/月，含全部推送、匹配排序、套磁信。 ¥29/月是待验证假设，不是定价结论。 验证方式：找 3 位目标用户，至少 1 位愿意为 「不漏公告 + 可回原文」付这个价；在此之前不把它写成已成立的商业模式。
  2. B 端：院系招生宣传、教育机构的数据接口（合规前提下）。
  3. 开源/社区：代码公开，数据脱敏；通过部署服务与定制采集收费。

当前支付为模拟（开通码），未接真实通道；不把模拟开通写成营收。 真实用户试用（docs/USER-TEST.md 的流程）尚未执行，是交付里明确标注的待补证据。

8. 合规与边界

  • 数据来自各高校公开官网，遵守礼貌间隔，不绕过验证码与访问限制。
  • 公开仓库与演示站不含考生名单、手机号等个人信息；部署版数据经过脱敏脚本处理。
  • 不做：录取概率预测、选校推荐、历年分数线——没有数据支撑的结论一律不做。
  • 已知边界（主动写在 README 与演示页）：
  • 上海交大详情页为 JS 渲染，正文抓不到；
  • 扫描版 PDF 无 OCR；
  • 微信公众号无开放接口；
  • 其余 26 所学校尚未做漏检对照；
  • 单 worker、JSON 状态，暂不支持大规模并发。

11. 团队与校园试点

11.1 每个人踩过的一个坑

角色 实际负责 踩过的坑 → 怎么改的
A · 数据 抓取、抽取、分类、去重、质量门禁 定时任务把 2751 条公告写残成 69 条，持续 3 小时没人发现 → 改成写 .tmp 后 os.replace 原子替换，再加「条数骤降 20% 拒绝落盘」
B · 服务 35+ 接口、打分、状态、233 条门禁 门禁只测接口形状，测不出上海交大 46 条正文是空的 → 增加 11 条数据健康断言（空壳、未知占比突变、悬空事件）
C/F · 前端 11 个页面、移动端、演示 心跳接口 0.5 秒卡住首屏 → 改成 load 之后空闲时异步拉，首屏不再等它
统筹 交付节奏与验收 轻信自我汇报，把一个「没重启服务」的改动判成「没做」→ 现在每条验收先看进程启动时间，再看页面
QA（只读） 每轮自己跑门禁、走学生画像 所有「自述与实测不符」的问题最后都是 QA 发现的，不是开发的人发现的

协作方式是「目录所有制 + 契约先行」：改动先改契约，再改实现，门禁必须绿。

11.2 校园试点（可执行）

  • 学校 / 对象：浙江大学物理学院、材料科学与工程学院，大三下准备推免的学生（每年约 200 人）。
  • 社区能提供什么：院系教务与学长学姐渠道，帮我们约到 3–5 位真实用户做 15 分钟试用。
  • 成功指标（三条，缺一不可）： 1. 能不能在 60 秒内找到某条公告的截止日； 2. 会不会主动回访（第二天还打开、或问「有没有新的」）； 3. 是否愿意为「不漏公告 + 可回原文」的提醒付费。
  • OPC 契合度：我们不硬蹭没有可靠公开说明的机制；按上面的校园试点讲清楚 「项目怎么进入真实用户、社区怎么协作、用什么指标判断成功」。

12. 一句话收尾

这个项目最值钱的不是 2,646 条数据，是它对「不知道」的处理方式。

读不到截止日就说读不到；没有对口公告就说今天没有；判据错了就把判据和实测一起写下来，让下一个人能推翻它。 守住这三条，29 所学校也是可信的；丢了它们，200 所也只是另一堆没人敢用的数据。
